# 電話推廣名單系統

把 Google 雲端硬碟「電話推廣名單」資料夾裡的名單 PDF，變成可以搜尋、篩選、
一鍵撥號、記錄追蹤的工作台。純前端網頁，**名單資料只留在你自己的瀏覽器裡**，
不會上傳到任何伺服器。

## 怎麼用

1. 開啟網站（見下方「啟動方式」）。
2. 首次開啟會跳出匯入視窗，把 PDF 拖進去，或按「選擇檔案」一次選多份。
   - 支援雲端硬碟裡的四份名單：重點追蹤名單、重點追蹤名單（2019年前）、
     從未打過、與中租往來名單。
   - 也吃試算表匯出的 CSV。
3. 匯入後就會停在「今日待打」，那是**下次聯絡日已經到期或逾期**的客戶。
4. 點卡片上的電話直接撥號（手機上會叫出撥號程式），講完在詳細頁
   「記錄這通電話」寫下結果並排下次聯絡日。

名單檔名會變成「名單來源」標籤，之後重新匯入同一個檔名 = 更新那份名單，
你自己記的通話紀錄不會不見。

## 功能

- **今日待打**：依下次聯絡日自動排隊，逾期的排最前面並標紅。
- **搜尋**：公司、統編、負責人、KEYMAN、電話、地址、訪談內容全文搜尋，
  空白分隔可以多關鍵字交集（按 `/` 直接跳到搜尋框）。
- **篩選**：聯絡時程、分級、洽談狀態、縣市、客戶規模、往來情形、資料完整度（有無統編、有無電話，可疊加）、變更登記、歸屬分公司、
  產業別、名單來源（名單來源放最後，看的頻率最低）。
- **洽談狀態**：從訪談內容自動判讀（未接通／已聯絡／有意願／已約訪／婉拒／
  禁止推廣），標成「禁止推廣」的預設不顯示，避免又打過去。
- **訪談時間軸**：PDF 裡擠成一坨的訪談內容會拆成一則一則（民國年自動換算），
  你自己新增的紀錄排在最上面。
- **今日推薦**：每天打開自動把值得推廣的挑出來、排好順序、寫清楚為什麼（增資、有機會、
  以前往來過、有設備標的、資本額落在可做的區間、逾期、太久沒聯絡…），一鍵排到今天或略過 30 天。
- **新公司名單（獨立網站 `leads/`）**：GitHub Actions 每月把經濟部的公司設立／變更登記清冊
  （含案由與營業項目）抓成 CSV，獨立網站上篩增資、縣市、行業、資本額，匯出的 CSV 拖回
  這裡的「新增客戶」就匯入。
- **找電話（Google 地圖）**：沒電話的客戶，詳細頁一顆鈕用 Places API 查店家電話（用你自己的
  金鑰、從你的瀏覽器直接查），確定的一鍵採用，找不到就刪；選單裡可以整批找。
- **拜訪準備**：出門前一頁看完這家——基本資料、登記動態、往來情形、最近談了什麼、
  這次要問什麼（從增資、負責人異動、往來銀行、本餘等推出來的提問清單）。可列印、
  複製成文字、一鍵導航到實際地址。
- **記錄這次拜訪**：跟記通話分開的短表單——見到誰、談了什麼、資金需求、下一步、
  有沒有機會、下次聯絡日。存成一則「拜訪」紀錄，「已拜訪」標記與篩選直接認它。
- **撥號**：電話欄裡的多支號碼、分機、括號註記都會拆開，分機用 `tel:` 的
  暫停碼自動續撥。每支號碼旁邊都有「複製」，複製的是純數字，貼到撥號鍵盤
  直接可用（分機會在提示訊息裡另外告知）。
- **統計**：逾期／到期數量、分級、來源、縣市、產業分布。
- **匯出**：CSV（含自己記的通話紀錄，Excel 可直接開）、JSON 備份與還原。
- 深色模式、手機版面。

## 啟動方式

### 給團隊用：GitHub Pages（推薦，手機也能開）

1. 到 repo 的 **Settings → Pages**。
2. Source 選 **Deploy from a branch**，Branch 選 `main`、資料夾 `/ (root)`，Save。
3. 等一兩分鐘，網址是 `https://<帳號>.github.io/asaaaa/`。手機瀏覽器開這個網址，
   再「加入主畫面」就跟 App 一樣。

網址是公開的，但**網站本身不含任何名單資料**——PDF 是每個人在自己瀏覽器裡匯入的，
不會上傳。別人打開只會看到空白的匯入畫面。

### 電腦上單機用：直接開檔

Code → Download ZIP → 解壓縮 → 雙擊 `index.html`。Chrome 與 Edge 實測可用
（pdf.js 會自動改用主執行緒解析）。若瀏覽器擋住本機檔案，改用下面的方式。

### 本機起一個伺服器

```bash
# 專案根目錄擇一執行，然後開 http://localhost:8000
python3 -m http.server 8000
npx serve .
```

## PDF 是怎麼讀出來的

試算表列印成的 PDF，直接抽文字會把多行儲存格的內容交錯在一起，根本分不出欄位。
所以 `assets/js/pdf-table.js` 改成：

1. 把每頁算圖到 canvas，掃描像素找出表格的**框線**，還原真正的儲存格網格。
2. 依文字的座標把它丟進對應的儲存格。
3. 分辨「欄寬不夠自動折行」與「使用者按的換行」——前者一路寫到儲存格右緣，
   接回去才不會出現「律果科技股份有／限公司」這種被切斷的字。
4. 跨頁被切成兩半的資料列，依頁首／頁尾位置接回同一筆。

`assets/js/normalize.js` 再把表格轉成客戶資料：對應欄位標題、民國年換算、
拆電話與分機、依公司型態字尾拆出關係企業、切訪談時間軸、抓縣市行政區。

只靠欄位位置是不夠的——PDF 少偵測到一條直線、或表格有合併儲存格，整列就會平移，
訪談內容就會跑到「成立年」底下。所以每個欄位都有自己的內容驗證（統編要 8 碼數字、
成立年要 4 位年份、資本額要純數字、日期要解析得出來），並且：

1. 先拿前 40 列試算 −4～+4 的整體位移，挑驗證通過最多次的那一個，修正全表錯位。
2. 逐列檢查，位置上的內容驗證不過就在整列裡改用內容找正確的格子。
3. 三個日期欄長相一樣，先照表頭位置分配，補不足的再依「名單新增 ≤ 最近聯絡 ≤ 下次聯絡」排序。
4. 驗證不過又找不到替代的就留空白，不會塞錯的值進去。

匯入完會顯示前三筆的欄位對照，可以當場核對有沒有跑錯格。

如果某份 PDF 沒有框線，會退回以座標推測欄位，匯入訊息會提醒你抽查。

## 改版後要記得換版本號

靜態主機（GitHub Pages）會把 `js`／`css` 快取起來，所以只是推上新程式碼，
使用者的瀏覽器還是會用舊檔案，看起來像「功能沒出現」。

因此 `index.html` 裡每個 assets 網址都帶 `?v=日期-序號`，`assets/js/app.js`
最上面的 `APP_VERSION`、根目錄的 `version.json` 都是同一個字串。
**改動 js 或 css 之後，這三處要一起換掉。**

不過 `index.html` 本身也會被快取（GitHub Pages 約 10 分鐘），所以就算資源網址
帶了版本號，使用者還是可能停在舊版。因此開啟網站時會抓一次
`version.json?t=<時間戳>`（`cache: 'no-store'`，永遠不吃快取）跟 `APP_VERSION`
比對，不一致就跳出「網站有新版本可用」，按下去會用帶參數的網址重新載入，
強迫瀏覽器重新抓 `index.html`。

版本號也會顯示在 ⋯ 選單最下面，要確認對方跑的是哪一版時看那裡。

## 公司規則與案件檢核

「規則」分頁放公司規章原文，附帶檢核工具，最上方是一張把各條規則串起來的分析卡。

目前收錄五條：

| 規章 | 重點 |
|---|---|
| 案件償還本金管理辦法 第四條、第九條 | 每 6 個月至少累計償還起租本金 10% |
| 案件協銷及客戶移交　業績及淨收益分享原則 | 協銷分享一年、移交二年；微企處單戶上限 16,000 仟元 |
| 【微型企業營業處】行銷規範 | 資本額 ≤10,000 仟元為微企客戶；單戶授信上限 7,000 仟元 |
| 一般組及微企處之收益率控管規範 | 一般組做 7,000 仟元以下案件，Spread 須高於 9% |
| 行銷區域劃分與客戶歸屬 | 依公司登記地址劃分；跨區一律協銷；180 天歸屬期限 |
| 各分公司行銷區域劃分表（第 3～4 頁） | 北一／北二／中區／南區分處各分公司的縣市、行政區；【 】內為共同區 |
| 附表一：共同區域與被申覆單位（第 5 頁） | 共同區申覆以原始歸屬單位為對象；「擇任一方」可參考 EIP 拜訪紀錄 |
| 存貨擔保融資（第 5 頁） | 高屏一科、二科專屬，全台可做，倉儲須在台中（含）以南且經認可 |
| OSF 案件（第 5 頁，截斷） | 境外法人申戶仍受單一歸屬；以母公司登記地址認定 |

三個工具：

- **案件檢核**——輸入起租本金、期間、還款方式、擔保品、還款計畫，判斷是否受第四條
  管制，並逐一列出每 6 個月檢核點的應累計、實際累計、本金餘額與差額（含第九條例外）
- **分享比例試算**——選情境（協銷／移交、一般／微企、主動／被動、第一筆／後續），
  算出雙方業績與淨收益金額，微企處超過單戶 16,000 仟元上限會自動封頂
- **承作單位與協銷／移交判定**——輸入資本額、累計往來、Spread、歸屬與跨區狀況，
  列出該走協銷、移交還是可直接承作，以及各項門檻是否觸發

名單頁也接上了：

- 詳細頁多一列**行銷區域**：依「公司登記地址」（規範的認定基準，跟看實際地址的服務區域不同）
  對到劃分表，顯示「新莊分公司（北二分處）」；落在共同區的顯示共用的分公司與附表一的申覆對象，
  例如「城北、新莊分公司共同區（申覆對象：城北分公司）」；澎湖、金門、連江為全公司共同區域。
  行政區帶不帶「區／鄉／鎮／市」字尾都認得。卡片也標「新莊分公司」或「城北／新莊共同區」，
  篩選區有「歸屬分公司」下拉選單可直接挑出某分公司的客戶。
- **電話一支一列**：編輯客戶、手動新增的電話欄改成列表，每列號碼、分機、備註，可刪、可「＋ 加一支電話」；
  存回去時一支一行（「0936-570087 分機23 (馬少軒)」）。拆電話時備註只看到下一支電話之前，號碼前面的
  名字（「馬少軒0936-570087」）也當備註，卡片會顯示「0936-570087 · 馬少軒」。
- **公司名稱旁有「複製」**：詳細頁公司名稱右邊一顆複製，跟電話的複製一樣。
- **回撥提醒**：客戶說「晚點再打」，在詳細頁「回撥提醒」按「30 分鐘後」「1 小時後」「14:00」或自訂
  時間（可加備註），記在該筆的追蹤狀態並跟著雲端同步。名單頁最上面有提醒列，列出所有提醒、
  時間到變紅、跳提示與震動，開了瀏覽器通知會發通知（點通知直接開該客戶）；列上可「完成」
  或「延 15 分」。卡片標「⏰ 14:00 回撥」。沒有後端，只有網站開著（或裝成主畫面 App）時才會提醒。
- **提醒列一份清單**：回撥提醒與今天到期合在一起，同一家只列一次；每列「時間｜公司＋窗口、電話｜動作」，
  電話可直接撥；標題可收起，說明放在按鈕的提示裡。
- **下次聯絡日也是提醒**：訪談紀錄填了下次聯絡日的，當天打開網站就列在提醒列「今天要聯絡」，
  跳一次提示與通知（一天一次），有「只看今天到期」可直接篩；不用再另外設回撥時間。禁止推廣的不列。
- **訪談紀錄顯示儲存時間**：網站上記的通話在日期後面帶時間（2026/09/18 11:00），匯出的訪談
  內容也寫成「115/09/18 11:00 [已聯絡] …」，重新匯入時時間另外收起來，不算內容。
- **承作檢核**（詳細頁「承作檢核」按鈕）：輸入案件架構（金額、期數、繳款頻率、還款方式、擔保品、
  Spread、實質收益率、既有本餘、移交方式、案件類型）與我的分公司／單位（會記住並同步），網站拿
  名單資料（登記地址→行銷區、資本額→規模）與訪談內容（往來單位、本餘金額，含網站上記的通話）
  對照規則：行銷區域（別分公司的共同區：客戶沒跟該區往來就可申覆承作，有往來才要協銷）、微企處舊戶的申覆／移交與單筆最低起租、收益率控管、存貨擔保
  融資專屬、OSF 歸屬、案件償還本金管理辦法的檢核點（資本額屬不屬微企範疇這條使用者說與其規則無關，不列）。結果分「衝突／注意／符合」並給調整建議；
  判讀出來的事實（含訪談片段）攤開讓人覆核。判斷邏輯在 rules.js 的 checkDeal，本餘解析在 parseBalance。
- **記通話的快速日期**多一顆「今天」。結果選「禁止推廣」時不用填內容或下次聯絡日就能儲存。
- **KEYMAN 自動判讀**：從訪談內容（含網站上記的通話，新的優先）找 KEYMAN：明講的「KEYMAN 是陳經理」
  最準，其次看「姓＋職稱」（老闆、總經理、財務、會計、經理、小姐…，越接近決策者權重越高，同權重取
  最新）；「楊小姐接電話，他應該不是 KEYMAN」這種否定句會把該人排除；總機、櫃台不算。優先順序：
  使用者自己改過的 > 訪談明講 > 名單檔原本的值 > 訪談稱謂判讀 > 負責人。詳細頁會註明來源與依據。
- **通話紀錄草稿**：打到一半關掉視窗、切到別家或畫面重畫，字都會留著（每家各一份、存在這台裝置），
  回到那家自動填回來並註明；存好紀錄才清掉，也可「丟掉草稿」。
- **關係企業的訪談紀錄互通**：同一組的公司在詳細頁看得到整組的通話與訪談內容（標出是哪一家的，
  同內容只列一次，照日期排），往來情形、拜訪、KEYMAN、承作檢核的判讀也看整組。記通話只寫自己這家，
  不再每家各寫一則；別家的紀錄要到那家去改。
- **關係企業連結兩邊互相備援**：連結時每家都記整組成員；某一家的組別被別的來源蓋掉時，只要
  另一家還留著，打開就自動補回並寫回。明確「解除連結」的紀錄比備援新就尊重解除。
- **關係企業的日期連動**：手動連結成同一組（同老闆）的公司，下次聯絡日、最近聯絡日以整組
  「最近聯絡日最晚的那家」為準套到每一家（它沒填下次聯絡日就取整組最晚的），撥打狀態也
  跟著那家（禁止推廣的不動）。只影響顯示、篩選、排序，不改各家存起來的資料。
- **篩選晶片的家數即時連動**：每一組的數字是套用「其他所有條件」（含搜尋、隱藏禁止推廣）之後的家數，
  自己這組不算進去，所以點了「無電話」後「有電話」不會變 0，可以換著看。歸屬分公司下拉的數字也一樣。
- **篩選區每一組可收合**：點標題展開／收起；手機上預設只展開聯絡時程、洽談狀態、歸屬分公司、
  排序，其他收起來只留標題與「已選幾個」的數字；電腦版預設全開。收合狀態記在該裝置。
- 客戶資本額未達 5,000 仟元（不含）標示「微企範疇」、≥500,000 仟元標示「大企部範疇」，
  中間是「一般組範疇」，可依此篩選
- 依地址標示**服務區域**：新北市的新莊、三重、林口、泰山、五股、八里、淡水、
  蘆洲、樹林九區為「優先區域」；新竹以北加宜蘭為「服務範圍」；其餘標示
  「範圍外·需協銷」，詳細頁並註明依【一般組】行銷規範第(三)項應採協銷辦理。
  排序可選「依服務區域」把優先區域排前面。
- **往來情形採二分法**：「有跟中租往來」／「沒有跟中租往來」。看**最新一期**訪談內容
  （網站上記的通話也算）：寫到「本餘」（本餘／本金餘額／本於皆可——「本於」是誤植），
  或同一小句寫到中租體系單位還在往來（「目前還在跟中租往來」「跟大企有配合」），
  就是有往來，卡片標【中租往來】；跟銀行、同業合作不算。寫到解約、結清等合作已結束
  的字眼一律歸沒有往來。

  只看**最新一期**是關鍵：三年前的本餘早就還完了，拿舊紀錄判斷會誤判。
  有日期的訪談取日期最晚那筆，整段都沒日期就取最後一段。

- 詳細頁在結論底下另外列出判讀到的**往來對象**：中租其他單位（大企、微企處、
  融專、城北…）、同業（和潤、裕融、合迪、新鑫、台新租賃、中國租賃…）、銀行，
  並附上原文片段供核對。這是佐證用的參考資訊，不影響上面的二分法分類。

  名稱是從實際名單的訪談內容裡挖出來的。銀行名稱另外要求同一行出現金融往來字眼
  （額度、貸款、核准、撥款…）才算，避免「國泰、興富發、家泰」這種建商名單被誤判。

  這是在顯示時計算的，所以**既有名單不必重新匯入就會套用**。

判斷邏輯在 `assets/js/rules.js`，與畫面分離、有單元測試。要再加規章往 `RULES`
陣列加一筆即可，工具可選擇性掛上。

條文沒有明講、工具標示「請向風管／行銷管理科確認」而不自行認定的地方：

- 同時徵提可排除擔保品（如不動產）與須管制擔保品（如動產）時如何認定
- 承作期間超過五年時，超過五年的部分如何檢核
- 微企客戶移交表中，起租單位淨收益寫「50% 或 60%」，但微企處那兩列淨收益都寫
  40%，兩者對不起來。工具依「同傳統業績比例」把淨收益比照業績比例計算

## 編輯與新增客戶

客戶詳細頁的「編輯資料」可以改公司名稱、統編、分級、成立年、資本額、電話、
負責人、KEYMAN、產業別、地址與下次聯絡日。

**修改是存成覆蓋層，不會動到 PDF 解析出來的原始資料。** 所以：

- 重新匯入同一份 PDF 更新名單時，你改過的欄位不會被蓋回去
- 修改會跟著雲端同步帶到其他裝置（走的是同一套合併機制）
- 隨時可以「還原成名單原始內容」
- 改過的客戶會標示「已修改」

電話與地址改完會重新解析，所以撥號鍵與縣市篩選會跟著更新。

兩種不靠 PDF 加客戶的方式，來源都標記為「手動新增」，和匯入的名單分開管理：

- **貼上新增客戶**——從 Excel 或 Google 試算表選取整列複製，直接貼進來。自動判斷
  Tab 或逗號分隔，沒有標題列就依名單的標準欄位順序判讀，再用同一套內容驗證修正
  錯位。一次可貼多列；公司名稱與統編相同的會更新而不是重複新增。按下確定前會先
  預覽解析結果。
- **手動新增客戶**——一格一格填（適合只有名片、資料不多的情況）。

## 多裝置同步（Google 雲端硬碟）

手機和電腦的資料預設各自獨立。要互通，走這條：

1. 選單 ⋯ →「雲端同步設定」。
2. 照裡面的步驟建一個 Google OAuth 用戶端 ID，貼進去。**每台裝置貼同一個 ID、
   登入同一個 Google 帳號。**

   兩個最常卡住的地方：
   - 同意畫面的「**測試使用者**」要加入你登入用的 Gmail，否則會得到
     `403 access_denied：只有測試人員可以存取`。不想維護名單就按「發布應用程式」，
     `drive.file` 權限不需要送審。
   - 「已授權的 JavaScript 來源」只填到網域為止（`https://帳號.github.io`），
     不要加後面的路徑，否則會 `redirect_uri_mismatch`。
3. 之後每次開啟、每次記完通話都會自動同步，也可以按右上角 ⟳ 手動同步。

同步檔是雲端硬碟裡的一個 JSON（`電話推廣名單-同步資料.json`），由瀏覽器直接讀寫，
**不經過任何第三方伺服器**。授權範圍只有 `drive.file`——這個網站只碰得到自己建立的
那個檔案，你雲端硬碟裡其他東西它看不到。

合併規則，重點是**不會互相覆蓋**：

- 通話紀錄：兩台裝置各記各的都保留，靠每筆自己的 uid 去重
- 追蹤狀態（洽談結果、下次聯絡日）：同一筆客戶取 `updatedAt` 比較新的那份
- 編輯過的客戶資料：另外看 `editsAt`，所以另一台只是記了通話（`updatedAt` 比較新
  但身上沒有編輯內容）不會把編輯洗掉；還原也算一次編輯，同樣靠時間戳決定
- 名單：兩邊聯集；同一份 PDF 在不同裝置匯入會算出相同的 id，所以不會重複
- 刪除：刪掉的通話紀錄與名單來源會留下墓碑記錄，下次同步不會被另一台救回來
- 同一份資料重複同步不會愈長愈大（合併具冪等性）

選單裡的「還原備份 JSON」現在也是合併而不是覆蓋，所以不設定 Google 也可以手動
互傳檔案，不會弄丟東西。

## 隱私

名單含公司負責人姓名、電話與拜訪紀錄。這個網站沒有任何後端，
資料寫在瀏覽器的 IndexedDB。沒開雲端同步的話，換一台裝置或清掉瀏覽器資料就沒了——
可以用「下載備份 JSON」再到新裝置「還原備份 JSON」（會合併，不會蓋掉）。
開了雲端同步的話，資料額外存在你自己的 Google 雲端硬碟，一樣沒有第三方伺服器。
共用電腦用完記得用選單裡的「清除所有資料」。

## 每週公司登記資料更新（建置中）

`.github/workflows/weekly-company-sync.yml` 排在**台灣時間每週日 18:00** 執行
（cron 用 UTC，所以寫成 `0 10 * * 0`），也可以在 Actions 頁手動觸發。

會放在 GitHub Actions 而不是別的地方，是因為它同時滿足兩個條件：runner 的對外
網路沒有限制（開發環境連不上政府網站），而且不需要任何人的電腦開著。

目前是**探測階段**。`tools/probe-sources.mjs` 會去敲四個來源並把實際收到的東西
記錄下來，再據此寫真正的解析程式：

| 來源 | 要確認的事 |
|---|---|
| findbiz 查詢畫面 | 有沒有擋程式存取、需不需要 session |
| 商工行政資料開放平臺 公司登記基本資料 API | 回傳格式、查得到不 |
| 同上（帶 Origin 標頭） | **有沒有 CORS** — 決定網站能不能自己查 |
| 公司變更登記（增資）查詢頁 | 是靜態頁還是要帶參數 |

CORS 那一項是關鍵分歧點：

- **有 CORS** → 補資料做在網站裡，由你的瀏覽器直接查。客戶名單完全不離開你的
  裝置，結果透過既有的雲端硬碟同步到其他裝置。這是首選。
- **沒有 CORS** → 改由這個排程抓**整批**公開登記資料（不需要送出任何客戶名單），
  commit 成靜態 JSON，網站在瀏覽器裡用統編比對。一樣不外洩。

兩條路都刻意不把客戶名單放進這個**公開** repo。

## 欄位錯置的修復

匯入時人名欄位（負責人、KEYMAN）的驗證條件原本只管「26 字以內的中文數字」，
而「新北市新莊區幸福東路79號4樓」正好符合，於是 KEYMAN 會在第一輪就把地址搶走
並佔住那一格，等輪到地址欄時已經拿不到了。名單上大量的「未填地址」就是這樣來的
——**資料一直都在，只是掛錯欄位**。

三個地方一起改：

1. `looksLikeAddress()` 讓人名與產業別的驗證器排除地址長相的字串
2. `resolveRow()` 多一輪「地址優先卡位」：地址的驗證條件是所有文字欄位裡最嚴的
   （要同時有縣市和路街門牌），所以通過它的內容幾乎不可能是別的東西，先卡先贏
3. 匯入時就把錯置的地址歸位；曾有選單項目處理舊資料，使用者確認不需要後已移除。

同一批還修掉：

- **多家公司黏成一串**：`splitCompanyNames()` 原本把換行整個刪掉再靠公司字尾切，
  遇到沒有字尾的商號（「大同鐵工廠」＋「乙建設股份有限公司」）就會整串被當成一家。
  改成先照換行切、行內再用字尾切——PDF 解析那邊已經分辨過折行與真換行了。
- **改了地址但服務區域沒跟著變**：`view()` 原本先算服務區域才重新解析編輯過的
  地址，順序反了，於是拿到編輯前的舊縣市。

## 從商工登記更新公司資料

選單的**「從商工登記更新公司資料」**可以依登記資料校正統編、資本額、負責人與
登記地址。資料來源是**商工行政資料開放平臺**的公司登記基本資料，跟 findbiz 查詢
畫面同一份來源——findbiz 本身是給人操作的介面（要 session、可能有驗證碼），
沒辦法程式化存取。

**查詢由瀏覽器直接發出**，這是刻意的：客戶名單只存在使用者的裝置上，要在別的
地方查就得先把整份名單送出去。這樣送出去的只有一個統編，回來的是公開登記資料。

介面分成「先試一筆」跟「全部更新」兩段。這條路有一個沒辦法事先驗證的風險：
政府的 API 若不允許跨網域呼叫（CORS），瀏覽器會直接擋掉。與其按下「全部更新」
跑到一半才發現全軍覆沒，不如先花十秒確認，順便把原始回應攤開來看——欄位名稱
要是跟預期的不一樣，這時候就看得出來。

幾個實作上的決定：

- 欄位名稱用**候選清單**依序試，而不是寫死一個。開發環境連不上政府網站，沒辦法
  確認欄位到底叫什麼；猜錯一個名字就整個功能靜悄悄回傳空值，太危險。介面也會
  列出回應裡沒對應到的欄位。
- 登記資料的金額單位是**元**，名單上的資本額是**仟元**，不換算會差一千倍。
- 每筆間隔 0.3 秒，中途可停止。
- 更新一律寫成「編輯」，不動原始名單：登記資料未必永遠比業務手上的新（例如剛換
  負責人還沒登記），要保留得回原狀的路。每一筆都能在詳細頁還原。

### 官方 API 被 CORS 擋掉之後

實測結果：`data.gcis.nat.gov.tw` 不送 CORS 標頭，瀏覽器直接擋掉。所以查詢改成
依序試三個來源，官方留著是因為政府哪天開放就會自動生效：

| 來源 | 狀態 | 說明 |
|---|---|---|
| 商工行政資料開放平臺（官方） | 被擋 | 最正確，留著等政府開放 |
| g0v 公司登記資料（社群鏡像） | 可用 | 同一份資料，有開 CORS。**預設不啟用**，要自己勾 |
| 自架代理 | 可用 | 最可控，填網址就會用 |

g0v 預設不啟用是刻意的：那是第三方服務，就算送出去的只有統一編號（本來就是公開
資訊），也該由使用者自己決定，不該偷偷送。

#### 自架代理（Cloudflare Worker）

不想經過第三方就自己架一個，免費方案就夠用。到 Cloudflare Workers 建一個
Worker，貼上：

```js
const ALLOWED = 'https://data.gcis.nat.gov.tw/';
const ORIGIN = 'https://andy-zhang-22.github.io';

const cors = {
  'Access-Control-Allow-Origin': ORIGIN,
  'Access-Control-Allow-Methods': 'GET, OPTIONS',
  'Access-Control-Allow-Headers': 'Accept, Content-Type',
};

export default {
  async fetch(request) {
    if (request.method === 'OPTIONS') return new Response(null, { status: 204, headers: cors });

    const target = new URL(request.url).searchParams.get('url');
    // 白名單不要拿掉：沒有它，這個 Worker 就是任何人都能拿去轉打任意網站的跳板
    if (!target || !target.startsWith(ALLOWED)) {
      return new Response('只接受 data.gcis.nat.gov.tw 的網址', { status: 400, headers: cors });
    }

    try {
      const upstream = await fetch(target, { headers: { Accept: 'application/json' } });
      return new Response(upstream.body, {
        status: upstream.status,
        headers: {
          ...cors,
          'Content-Type': upstream.headers.get('content-type') || 'application/json',
          'Cache-Control': 'public, max-age=86400',
        },
      });
    } catch (err) {
      // 錯誤也要帶 cors，否則瀏覽器只會說「跨網域被擋」，看不到真正的原因
      return new Response('連不上政府網站：' + err.message, { status: 502, headers: cors });
    }
  },
};
```

連錯誤回應都帶 CORS 標頭是刻意的。少了的話瀏覽器只會報「跨網域被擋」，把真正的
錯誤訊息（例如網址不在白名單）整個吃掉，出問題時完全無從判斷。

設定步驟在網站裡也有一份（「從商工登記更新公司資料」→「怎麼架自己的代理」），
還附複製鈕——要設定的時候人在瀏覽器前面，不會跑去翻 README。

部署後把網址填進「從商工登記更新公司資料」的**自架代理網址**欄位即可（存在瀏覽器
本機，不會進版控也不會同步）。

那段白名單檢查不要拿掉：沒有它，這個 Worker 就變成任何人都能拿去轉打任意網站的
跳板。`Access-Control-Allow-Origin` 也建議維持指定網域而不是 `*`。

## 從訪談內容補上下次聯絡日

原本程式只從「下次聯絡日」那個日期欄位取值，完全不看訪談內容的文字。實際使用時
很容易把「約10/20再拜訪」打在內容裡就送出、日期欄留空，那筆客戶因此永遠不會出現
在今日待打——**寫了等於沒寫**。

`findFollowUp()` 補上這一段，用在記錄與修改通話時：日期欄空白就從內容判讀並補上，
並在提示訊息裡講明補了哪一天。使用者自己填的日期一律優先，不會被蓋掉。
（曾有選單項目批次處理舊資料，使用者確認不需要後已移除。）

判讀刻意訂得保守，因為猜錯會打亂整個聯絡排程：

| 規則 | 為什麼 |
|---|---|
| 只看每則紀錄的內文 | 開頭那個日期是訪談當天，拿來當下次聯絡日一定錯 |
| 同一則要有約訪字眼（再聯絡、再拜訪、回電、追蹤…）| 避免把金額、比例、電話號碼誤判成日期 |
| 只接受今天以後、一年半以內 | 過期的約訪與明顯離譜的日期都排除 |
| 只寫月/日時，同年那天要過去超過 180 天才推到明年 | 十二月寫「1/5」是跨年；九月寫「上次8/1有拜訪過」是在講過去，推成明年會憑空生出一個約訪 |
| 內文寫明的日期優先於該則開頭的日期 | 開頭是寫下的時間，內文的「約1/5再談」才是約好的那天 |
| 取最新一則的判讀 | 舊的約訪早就過期了 |

## 修改與刪除

- **修改通話紀錄**：自己記的每一則旁邊都有「修改」，可以就地改內容與日期。
  原本只有刪除，等於打錯字就得整則重打、日期與結果都要重選一次。
  PDF 原本的訪談內容不給改（那是名單來源，不是自己記的）。
- **刪除單一客戶**：詳細頁的「刪除這筆」。原本只能用「管理已匯入名單」整份刪掉，
  但實際會遇到的是單筆要移除（公司倒了、統編重複、明確表示不要再打），
  為了一筆重匯整份不合理。提示會列出會一起消失的通話紀錄與編輯內容。

兩個功能都牽動同步，各修掉一個會讓資料無聲消失的問題：

- **紀錄合併原本是先到先贏**，所以在這台改過的內容會被另一台的舊版本壓回去，
  而且畫面上看起來是存好了。改成比對 `updatedAt` 取比較新的那份。
- **`getTombstones()` 只挑出 `logs` 與 `sources`**，新加的 `records` 墓碑存得進
  資料庫卻永遠傳不出去 —— 刪除在本機成功，同步一次就被另一台救回來。
  每加一種墓碑都要記得列進那個回傳值。

刪除留墓碑但帶時間戳：比墓碑新的匯入可以回來，因為那是使用者自己又匯入了一次，
不是同步把刪掉的東西救回來。

## 版本號與更新

選單最下面會顯示**目前跑的版本**，旁邊有「檢查更新」。

會做這個是因為使用者一再遇到「我明明更新了，但畫面沒變」。真正的原因是瀏覽器
拿快取的舊檔，但**畫面上完全看不出自己跑的是哪一版**，只能瞎猜，每次都要靠猜
「是不是快取」來回好幾輪。有版本號就一秒確定。

- 「檢查更新」是使用者主動按的，所以已經是最新版也會回報；自動檢查則保持安靜，
  每次開啟都跳「已是最新版」很吵。
- 按過「稍後」把提示條收起來之後，再主動檢查一次仍然叫得出來。
- 除了載入時檢查，**切回這個分頁時也會再檢查一次**。原本只在載入時檢查，但常常是
  同一個分頁一直開著，那就永遠不會再檢查，更新了也不知道。

## 禁止推廣

客戶明講不要再打了，再打就是騷擾——這是所有標記裡唯一「不能出錯也不能被蓋掉」的。

原本它只是 `outcome` 的七個值之一，而 **`outcome` 會被之後記的通話紀錄覆蓋**：
隨便記一通「已聯絡」，禁止推廣就消失，那位客戶會悄悄回到待打名單裡。現在改成
直接從訪談內容判讀，跟 `outcome` 分開，**只能加不能減**（使用者自己選「禁止推廣」
也算，兩邊任一成立就是禁打）。

- 卡片上是紅色的【禁止推廣】標記，並取代原本的狀態標記（同一句話不用講兩遍）。
- 詳細頁的警告放在**電話號碼上面**，並附上原文。放下面沒有用——撥號鍵就在上面，
  看到電話就會直接按下去。
- 預設從名單裡隱藏（「隱藏禁止推廣」的勾選維持既有行為），洽談狀態的篩選也以
  這個為準。

用詞只收明確的拒訪語句。像「黑名單」「拒絕往來」看起來很像，但在金融業的訪談
紀錄裡通常是在講客戶自己的信用狀況（拒絕往來戶），收進來會製造假的禁打名單。

## 版本號的一致性檢查

版本號散在三個地方（`index.html` 的 `?v=`、`APP_VERSION`、`version.json`），
任何一處對不上都會出事，而且**不會讓任何功能測試變紅**：

- `version.json` 比程式新 → 更新提示無限迴圈（按了更新還是舊版，又跳提示）
- `index.html` 的 `?v=` 沒跟著換 → 使用者拿到快取的舊 js

`test-version-sync.js` 專門檢查這三處一致。加這支測試是因為真的踩到了：
從舊的分支切出來改版本號，取代字串沒命中，結果只有 `version.json` 被改到。

### 範圍只決定查哪些客戶，查到的差異一律直接更新

「從商工登記更新公司資料」的範圍有兩種，預設是**只查欄位有空白的客戶**：

| 範圍 | 查哪些 |
|---|---|
| 只查欄位有空白的客戶 | 統編、資本額、負責人、登記地址、成立年任一空著的那些（較快） |
| 查全部客戶 | 每一筆都跟登記核對 |

不管哪一種，查到跟登記不一致的欄位都**直接更新**，記成「已修改」，詳細頁可還原；
「變更登記」篩選也同時分類。以前分「只補空白、絕不覆蓋」與「全部校正」、查完還要
再按一次套用，實際用起來是：變更登記那邊已經看到增資、換負責人，欄位卻還是舊的——
查到了不更新，等於白查，所以改掉。

摘要會先算出筆數與預估時間（872 筆約四分半）。名單裡沒有缺欄位的客戶時，預設會
自動切到「查全部」，免得一按就撞到「沒有東西可以查」。

### 查詢語法試多種寫法

代理通了之後實測收到「回應不是 JSON」——代理沒問題，是政府那端收下了請求但回的
不是資料，多半是查詢語法不合它的胃口。OData 的字串比對通常要加單引號，但這支
API 的文件範例又常寫成不加，而開發環境連不上、驗證不了是哪一種。

所以查詢網址也改成**候選清單**（跟欄位名稱同樣的做法）：不加引號、加引號、
未編碼的 `$`，依序試過去，第一個回得出 JSON 的就是對的。介面會講明用的是哪一種寫法。

失敗訊息也補上實際收到的東西：**Content-Type、回應內容的前 300 字、實際打出去的
網址**。空白回應會明講「一個字都沒有」而不是含糊帶過。這類問題光看「不是 JSON」
完全無法判斷是政府端回了錯誤頁、回了空白、還是代理自己出問題。

跨網域被擋的情況會直接跳過同一個來源的其他寫法——那是整個來源的問題，換寫法沒有意義。

### 分辨「查不到」與「網址本來就是錯的」

實測用統編查，三種寫法全都回「Content-Type 是 JSON，但內容一個字都沒有」。
這個症狀分不出三件事，而三者的處理方式完全不同：

| 可能 | 怎麼辦 |
|---|---|
| 這個統編剛好沒有資料 | 換一筆再試 |
| 篩選語法不對 | 調查詢條件 |
| 資料集編號根本是錯的 | 換編號，調語法再久都沒用 |

所以在「所有收到回應的來源都是空的」時，會自動多做一步：**不帶篩選條件、直接跟
資料集要一筆**。資料集存在的話 `$top=1` 一定給得出來。

- 要得到 → 問題在查詢條件，不是網址。而且**回傳那一筆的欄位名稱就是這支 API 真正
  的欄位名稱**，順便解掉「欄位名稱只能用候選清單猜」那個問題。
- 要不到 → 資料集編號是錯的，會直接這樣講，不會讓人繼續在語法上鑽。

判斷「全都是空的」時只看**真的收到回應**的來源。官方那條永遠是跨網域被擋、根本沒
收到東西，算進去的話這個條件永遠不會成立——寫的時候就是這樣錯過一次。

## 檢查公司名稱

名稱錯就沒辦法拿去比對商工登記，而錯的名稱多半是解析留下的痕跡。選單的
**「檢查公司名稱」**把可疑的挑出來，分成兩堆處理，因為能做的事不一樣：

**可以自動拆開**——名稱裡有兩個以上的公司字尾，邊界很明確。第一家留作公司名，
其餘存成別名（搜尋一樣找得到）。

**要自己確認**——邊界無從判斷，自動改只會改錯。點名稱就直接開到那一筆修改。
會落在這一堆的情形：

| 判斷 | 例子 |
|---|---|
| 商號在前的黏合 | 大同鐵工廠｜乙建設股份有限公司 |
| 混到訪談內容 | 115/09/01老闆說有需求 |
| 名稱其實是地址 | 新北市新莊區幸福東路79號4樓 |
| 開頭是數字 | 38,000仟元… |
| 名稱過長（>24 字）| |

商號在前那一條**一定會有誤報**：「台灣工廠設備有限公司」跟「大同鐵工廠｜乙建設
股份有限公司」在結構上完全一樣，沒有任何規則分得開。但這只是列進清單、不會自動
改任何東西，所以寧可多報——誤報只花使用者一眼，漏報卻讓那筆永遠比對不到商工登記。

### 用名稱查要試幾種寫法

沒有統編的只能靠名稱查，而登記上的寫法跟業務手上的名單常常差一點點：

- **台／臺** 兩種都試（登記一律用「臺」，名單上兩種都有）
- 全形括號轉半形、空白清掉
- `like` 找不到再試 `eq`

## 匯入經濟部登記清冊

使用者每個月會去撈公司設立／變更登記的清冊找新線索。那種檔案一次四千多筆，
但真正要打的只有一小撮——他實際的篩選習慣是「資本額 6000 萬以下、在服務區域內」。

直接把 CSV 丟進匯入區就好，程式認得出那是登記清冊（看表頭有沒有統一編號、公司名稱、
公司所在地、代表人、資本額），會先跳出條件設定再匯：

- 資本額上下限（單位是萬元，跟使用者講話的單位一致）
- 地區：只要雙北／整個服務範圍／不限
- 可勾選略過**投資／控股類**

改條件時**即時重算筆數**，不用先匯進去才知道結果，並列出前五筆確認。已經在名單裡
的統編也會先講，免得匯完才發現重複。

投資控股那個選項是因為：這種檔案沒有行業欄位，但設備租賃做不做得成，看名字就有
八成把握——「精密工業」「機械」有實體設備可談，「投資」「控股」通常只有一張辦公桌。
推測歸推測，所以預設不勾，而且是標記在訪談內容欄、不是直接濾掉。

### 資料集網址可以自己填

程式裡預設的那串資料集 GUID 是憑記憶寫的。實測「不帶任何查詢條件、跟它要一筆」
也回空的，代表**編號本身是錯的**——查詢語法再怎麼調都沒用。

但開發環境連不上政府網站，查不出正確的編號。所以改成可以在介面上填：使用者從
開放資料平臺複製正確網址貼進來就能用，不必等我改一版程式再部署一次。
這種「只有使用者那一端查得到」的資訊，本來就不該寫死在程式裡。

貼進來時後面的 `?$format=...` 會自動去掉，只留資料集本身的網址。旁邊附上到哪裡
找的步驟。跟代理網址一樣存在各台裝置自己的瀏覽器裡。

兩個網址欄位各自有 id（`datasetUrl`、`proxyUrl`）而不是靠出現順序分辨——加第二個
欄位時三支測試同時壞掉，就是因為它們抓的是「第一個 url 欄位」。

## 名單新增的篩選

篩選面板的第二組（就在「聯絡時程」底下）是**「名單新增」**：
今天新增／7 天內／30 天內／一年內／更早／未填。
剛匯進來的那批按「今天新增」就圈得出來。

用「離今天多久」而不是列出每一個日期，是因為從 PDF 匯進來的客戶，名單新增日期是
來源檔裡的原始日期，散落好幾年、上百個不同的值——一個日期一顆按鈕會變成一面牆。
同一批匯入的會共用同一天，所以這幾個區間就夠用。

順序固定成由新到舊、不依筆數排：「今天新增」永遠在第一個位置才好按。

要精確找某一批的話，**「名單來源」**那個篩選更直接——匯入時的檔名就是來源。

## 拿掉「今日待打」分頁

使用者要求移除。功能沒有消失：左側**「聯絡時程 → 今天以前（待打）」**是同一件事，
而且可以跟其他條件疊加，原本那個分頁做不到。預設分頁改成「全部名單」。

## 聯絡時程的區間

原本只有「今天以前（待打）」「逾期」「一週內」「未排定」四個。實際用起來的問題是
**一顆按鈕給你 384 筆，等於沒篩**，而且看不出輕重——逾期一天跟逾期三個月要做的事
完全不同：前者補打就好，後者多半要重新評估或放掉。

拆成九個，**每一段都標筆數**：

| 區間 | 用途 |
|---|---|
| 全部 | |
| 今天以前（待打）| 每天的主力清單 |
| 今天到期 | 只看今天排的 |
| 逾期 1–7 天 | 剛漏掉的，最該補 |
| 逾期 8–30 天 | 拖了一陣子 |
| 逾期超過 30 天 | 要重新評估或放掉 |
| 明天 | 隔天的準備 |
| 未來 7 天 | 本週排程 |
| 未排定 | 還沒排過的機會池 |

刻意保留會互相重疊的區間（「待打」涵蓋今天與各段逾期）：這一組是**單選**，
重疊不會互相干擾，反而讓使用者先用大範圍看總量，再切進某一段處理。

標筆數是重點。沒有數字就看不出哪一段積最多，也就無從決定今天先處理哪一堆。

篩選條件與 chip 計數共用同一份 `DUE_RANGES` 定義，不會出現「按鈕寫 12 筆、點進去
剩 8 筆」這種兩邊各算各的問題。

### 拿掉手動的起～迄日期框

快速鍵下面本來還有兩個日期框可以自己框區間。使用者說用不到，占的位置卻不小（手機上
兩行），所以拿掉了。內部的區間邏輯留著——今天、本週、下週這些快速鍵就是換算成一段
日期去篩的，只是不再讓人手動輸入。

## 匯入時的重複處理：重複的一律不匯入

客戶的 id 是「檔名＋公司名＋統編」算出來的，所以同一家公司出現在不同檔案裡，會變成
兩張各自獨立的卡片。匯入時先跟名單上其他來源的公司比對（優先用**統一編號**，沒有統編
才退回公司名稱並把台／臺正規化），**比到的那幾列直接丟掉不匯入**，匯入紀錄講明略過幾筆、
各靠哪種比對。名單上那筆（打過的紀錄、找來的電話、改過的欄位）原封不動。

以前會跳對話框問要覆蓋、兩邊留、還是略過；使用者說「只要是重複的名單就不要匯入」，
就不問了。覆蓋在實務上只會出事：清冊那一列很薄（沒電話、沒訪談），覆蓋等於用薄的蓋掉
厚的，還把手動修改一起清掉。

要**更新**既有的一份名單，用**同一個檔名**重匯：同名重匯是「更新」不是「重複」，
會整份換成新內容而通話紀錄、追蹤狀態繼續掛在同一個 id 上（`deleteSource` 不留墓碑、
不清紀錄）。104 截圖與手動新增也一樣：已經在名單上的公司不會再進來。

## 日期一律顯示民國年

詳細頁的下次聯絡與最近聯絡原本寫成「115/10/01（2026-10-01）」，括號裡的西元
是多餘的——名單其他地方全是民國年，混著看反而像格式錯了。拿掉。

日期輸入框是 `<input type="date">`，顯示格式跟著瀏覽器語系走（使用者的電腦上是
`mm/dd/yyyy`），網頁改不了。選擇器本身很好用（有月曆、有快速鍵），不想換掉，
所以在旁邊補一個即時的民國年提示（`withRocHint`），選了什麼一眼就對得上。
記錄通話、編輯客戶、修改訪談紀錄三處的日期框都有。

快速鍵（明天、3 天後…）是直接改 `value`，不會觸發事件，要手動送出 `change`
提示才會跟著換——這種「程式改值、畫面沒跟上」的坑很容易漏。

## 舊徵信資料的清除

徵信資料功能移除後，瀏覽器裡還留著它的 IndexedDB（`crm-db`）。名單完全用不到，所以每台裝置第一次開到
20260919-104 以後的版本時會自動刪掉一次，並在 localStorage 記下 `crm-db-dropped`，之後不再重跑。
若當下還有別的分頁開著舊版徵信頁，瀏覽器會擋住刪除，那次就不記旗標，下次開網站再試。名單資料庫
（`telemarketing-db`）不受影響。

## 清除所有資料

舊版是把四個 store 全部 `clear()`，包括 meta。**在有開雲端同步時這是錯的**：同步是
「聯集」合併，本機清空之後下一次同步會把雲端那份整個合併回來，看起來就像清除失效；
而 meta 裡的墓碑和 `driveFileId` 也一起被清掉，等於把唯一能把「刪除」傳出去的機制
也砍了。

現在走既有的墓碑機制：每個來源、每則通話紀錄各留一個墓碑，再清掉資料。meta 不動
——墓碑要留著才傳得出去，同步設定也要留著。清完立刻同步一次把墓碑推上雲端，
不然要等下一次自動同步，中間別台裝置會先把舊資料推上去。

之後匯入的新名單 `importedAt` 會比墓碑新，照常存活，跟重新匯入同一份 PDF 的行為一致。

不可逆又會傳到所有裝置的動作，所以：兩次確認、講明筆數與同步影響，並在動手前
**自動下載一份備份**。測試裡驗證「本機（空＋墓碑）跟雲端（完整）合併」兩種順序
都得到空的。

## 匯入 Excel

拖 `.xlsx` 進去就好，跟 PDF、CSV 走同一條解析流程。只讀第一個工作表——公司匯出的
名單只有一張。

用的是 SheetJS 的 **mini** 版（`assets/vendor/xlsx/xlsx.min.js`，250 KB，Apache-2.0）
而不是 full 版（880 KB）：所有資產共用同一個 `?v=`，每次改版都會重新下載，
手機上差三倍很有感。mini 版讀 .xlsx 夠用，用使用者實際的公司主檔（872 筆）驗過。

日期格用 `cellDates` 讓 SheetJS 直接給 Date 物件再自己轉成 `YYYY/MM/DD`。不這樣做
的話拿到的是 Excel 內部的序號（45914 之類）或跟著電腦語系走的字串，兩種都會讓
日期解析失敗。

### 資本額的單位

名單的慣例是**仟元**（PDF 上寫 38,000 就是三千八百萬），但公司匯出的 xlsx 是**元**
（寫 30000000）。直接匯進來會差一千倍，把五十萬變成五億。

匯入時看整欄的**中位數**判斷：中小企業的資本額用仟元表示多半在幾千到幾萬之間，
用元表示則是幾百萬起跳，中間隔了兩個數量級，20 萬這條線離兩邊都很遠。看起來是元
就**問一次**要不要換算——不自動換，因為換錯比不換更糟；看起來已經是仟元就不打擾。
值太少（不到 5 筆）就不猜。

### 同名欄位以「更新版」為準

公司主檔有兩欄「名單新增日期」：「(必填)」與「(更新版)」，122 筆不一致。使用者確認
「更新版」才是正確的，所以表頭偵測遇到同一個欄位出現兩次時，標著「更新」的那欄優先。

## 104 截圖直接變名單

業務在 104 看到正在徵才的公司會截「公司簡介」頁存起來。把截圖（PNG／JPG，可多張）拖進匯入區：

3. **預覽可改**：每家一張卡，辨識錯的字直接改。按「查商工登記」以公司名稱查（`registry.js`，

4. **電話規則**：只用公司頁上顯示的號碼，「暫不提供」就留白，不拿職缺頁的聯絡分機湊。
5. 加入時來源標為 `104截圖-YYYYMMDD`，訪談內容是 104 的背景資料（沒有日期，狀態為未撥打），
   跟名單上任何一家重複會問要覆蓋、並存還是略過。

## 商工登記查詢與每天自動更新

- 查詢走商工行政資料開放平臺的資料集：用統編查 `7E6AFA72-…`（公司登記基本資料-應用一，
  `Business_Accounting_NO eq 統編`，有資本額、負責人、所在地、設立日期），用名稱查 `5F64D864-…`
  （公司登記關鍵字查詢，`Company_Name like 名稱 and Company_Status eq 01`——沒帶 Company_Status
  就查不到）。`$` 照字面寫，不編碼成 %24。兩個網址都可在設定視窗改。
- 舊的 `236EE382-…`（公司登記基本資料）實測只回統編、名稱、狀態、設立日期、營業項目，沒有資本額、
  負責人、地址，所以之前會「查詢成功但資料查無」。現在留作備援：統編查到的欄位不齊就換下一個
  資料集，最後再用公司名稱查補上（名稱查回來的統編要對得上才採用）。
- 這支 API 沒有 `$filter` 就回空白，所以「不帶條件要一筆」永遠是空的；探路改查一家一定
  存在的公司（台積電，統編 22099131）：查得到就是路通、資料集對。
- 官方 API 不送 CORS 標頭，瀏覽器直接連一定被擋；要靠使用者自架的 Cloudflare Worker 代理
  （設定視窗有腳本，含白名單與瀏覽器 User-Agent）或 g0v 鏡像。
- 診斷時每一條查詢網址都附「在新分頁打開」：那是使用者的瀏覽器直接連政府網站，不受跨網域
  限制，能直接看到政府回什麼。
- **每天 0:00 自動更新**：網站沒有後端，瀏覽器關著的時候不可能自己跑；做法是
  **網站開著就跨過 0:00 自己開跑，沒開著就等下次打開時補跑**，把全部名單對一次
  商工登記（統編、資本額、負責人、登記地址、成立年），差異直接套用並記成「已修改」，
  可在詳細頁還原；一路失敗就當天停手、明天再試，結果摘要顯示在設定視窗。
  判斷用的是「每分鐘看一次日期跳了沒」，不是「算到下一個午夜的 `setTimeout`」——
  筆電闔上、手機鎖屏的時候長計時器不會準時醒來，睡醒那個時間點早就過去了；
  日期沒跳時 `maybeAutoRegistry()` 只是讀一個 localStorage 就回來，不花成本。
  手機解鎖回到網站（`visibilitychange`）也補查一次，因為背景分頁的計時器會被節流。
- **變更登記篩選**：每次查核（自動或手動）都把結果分類記在該筆客戶上：增資（資本額變大）、
  減資（變小）、變更登記地址、負責人異動、其他（統編、成立年）、無變更（查過且資料一樣）、
  未查核（還沒查過）。一家可以同時屬於多類；原本空白後來補上的不算變更。有異動的會保留
  最近一次的異動與日期，不會隔天套用完就變回無變更；詳細頁列出欄位前後值與最近查核日。
  查不到的也記下時間與原因，詳細頁分得出「還沒查」與「查了查不到」（篩選都算未查核）。
- **每天自動更新預設開啟**（設定視窗可關）；**新增客戶後立刻查核**：有開每天自動更新時，手動新增、貼上、104 加入的客戶存完就在背景查一次，
  不用等隔天；來源掛了就不記成查不到。

## 商工登記更新在背景跑

「全部更新」按下去以前，設定視窗會一直卡在畫面上，整份名單等於停用——但那一輪
少則幾分鐘、多則十幾分鐘，業務這段時間正好該在打電話。所以改成背景作業：

- 按下「全部更新」，設定視窗**自動收起來**，名單、搜尋、詳細頁、撥號全部照用。
- 畫面**右下角一顆小進度條**（約 194×35，只佔一行）：「登記更新 8/40　已更新 3」
  加一顆「停止」，底緣一條 3px 進度線。跑完變成「登記更新完成　更新 10／查不到 3」，
  按「關閉」收掉。第一版做成置中 560px 兩行的大橫條，實際用起來會擋到名單最下面那張
  卡片，所以縮到角落；查到哪一家改放在滑鼠提示（title）裡，完整結果摘要在設定視窗看。
- 每查完一筆**立刻寫進資料庫**，不是等全部跑完才一起寫。中途停止、關瀏覽器、
  手機切到別的 App 被系統收掉，已經查到的都留著，不用從頭再來。
- 回頭打開設定視窗，看得到「更新進行中」或上一輪的結果與前 20 筆差異；更新期間
  「先試一筆／全部更新」是停用的，免得同時跑兩輪。

實作上有一個不能省的細節：**成功的每筆即時寫、查不到的留到最後一起寫**。
「來源掛了」是靠「一筆都沒查到 ＆ 全部失敗 ＆ 沒有任何一筆是查到卻沒資料」判斷的，
失敗若也即時寫入，來源整個掛掉時會把全名單蓋成「查了查不到」——那比沒查還糟，
因為「未查核」會消失，隔天就不會再排進自動更新。

每天自動更新走的是同一條路（`runRegistryJob`），所以它也看得到進度、也能中途停止。

## 資本總額、實收資本額、最近核准變更日期

商工登記那一頁有兩個資本額數字，以前只收一個：資本總額查不到就拿實收頂著，結果
名單上那一格到底是哪一種說不準。實際踩到的樣子是這樣——名單原本帶的是**實收**
資本額 491,600 仟元（公司給的檔案多半填實收），查完被**資本總額** 1,200,000 蓋
過去，變更登記那邊就冒出一筆「增資 491,600 → 1,200,000」。公司根本沒增資，是兩
個欄位混在一起。

現在三個分開收：

| 欄位 | 來源 | 用途 |
|---|---|---|
| 資本總額（仟元） | `Capital_Stock_Amount` | **微企／一般組／大企部就是看這個分的** |
| 實收資本額（仟元） | `Paid_In_Capital_Amount` | 另外存一格，詳細頁看得到 |
| 最近核准變更日期 | `Change_Of_Approval_Data` | 民國轉西元；登記最後一次異動的日期 |

兩個防呆：

- **舊值剛好等於這次查到的實收，就不算增資**。不擋的話，第一次查完整份名單會冒
  出幾百筆假的增資，業務照著打就白跑。
- **核准變更日期本身不算一種「變更登記」**。公司只要動任何登記它就會變，把它算
  進去等於每次有異動都多一顆「其他」，真正變了什麼看欄位前後值就夠了。

貼上商工登記查詢頁的整段文字（新增客戶那邊）也照收這三個欄位。

## 有機會／無機會

「這家願意給資料評估」只有打過電話的人知道，所以這個標記**只收手動的**，不從訪談
內容猜——猜錯會讓業務照著錯的名單打，比沒有這個欄位還糟。

- 詳細頁公司名稱下面兩顆：**有機會／無機會**，標起來的那顆會填色。
- **再按一次同一顆就取消**，回到「未判斷」。判斷會變（今天說要資料、下週說不用
  了），沒有取消的路就只能在兩個錯的之間選一個。
- 卡片上看得到標記，篩選多一組「有沒有機會」：有機會／無機會／未判斷，家數跟其他
  條件連動；手機上這組預設展開。
- 跟著雲端同步，合併時比 `chanceAt`（取消也算一次標記，所以時間戳一樣要更新）。

## 同一天記兩則時，「最新一則」取錯的 bug

訪談內容的慣例是**新的在最上面**，所以日期一樣的時候，越上面越新。`latestNote()`
原本用 `>=` 比日期，同日的下一則（其實是比較舊的那則）會蓋過上面那則：今天先記
「和潤那邊解約了」、再記「新設備案本餘 150 萬」，往來情形卻還停在「沒有往來」，
卡片上顯示的最新一則也是舊的。改成 `>` 之後，同日取寫在上面的那則。

`test-dealing-ui.js` 一直紅著就是在講這件事（「最新一則又有本餘 → 有往來」）。

## 二分法的篩選改成單選

「有拜訪／無拜訪」這種兩顆一組的篩選，同時選兩顆等於沒篩（那就是全部），但畫面上
兩顆都亮著，看起來像有在篩——名單為什麼是這些就講不清楚了。所以這幾組改成單選：
按另一顆就換過去，按已經選的那顆就取消。

| 單選 | 複選 |
|---|---|
| 資料完整度（有／無統編、有／無電話）、拜訪、往來情形、有沒有機會、名單新增 | 名單來源、洽談狀態、縣市、客戶規模、變更登記 |

複選那幾組疊起來是有意義的：台北＋新北、微企＋一般組、增資＋減資，都是同一個問題
的不同答案，選兩個等於「這兩種都要看」。二分法沒有這回事。

「資料完整度」裡的統編與電話是**兩組**，各自單選，所以「有統編＋無電話」仍然疊得
起來——那正是「資料缺電話要補」的名單。

## 查核欄位改版時自動重查一次

「每天只跑一次」是靠記下當天日期擋的，所以**改版當天新增的查核欄位會整天都是空的**
——那天的自動更新在改版前就跑完了，新欄位得等隔天 0:00 才補得到。使用者看到的是
「你說有這兩欄，我這裡沒有」。

所以加了 `REGISTRY_FIELDS_REV`：改欄位時換這個字串，網站下次打開發現對不上，就把
「今天已經跑過」的記號清掉，立刻在背景重查一次全部名單。這個記號也跟著雲端同步，
某台重查完、資料同步過去了，另一台就不會再查一次。

## 排序：依最近核准變更

排序多一個「依最近核准變更（新到舊）」，剛動過登記的公司排在最前面——增資、換
負責人、搬家這些事情剛發生的時候最好談。沒有日期的排最後。排序那一組也從側邊欄
最下面搬到「名單新增」下面，那是每天都會動的東西，放在最底下要捲很久。

### 「1911年0月0日」照原樣顯示

設立後沒核准過變更的公司，登記上的「最後核准變更日期」是民國 0 年 0 月 0 日，
查詢頁就是寫「1911年0月0日」。g0v 鏡像回的是 `{year:0,month:0,day:0}`，原本被
`flat()` 當成空值丟掉，整列就不見了——看到的人只會以為是網站漏了，還得自己再查
一次才知道是真的沒有。現在照原樣顯示成「1911年0月0日」，跟自己去查登記看到的
一模一樣；詳細頁那一列也一律出現，沒查過就寫「還沒查過商工登記」。

## 遇到假日自動順延到上班日

「三天後回電」如果落在連假，那通電話等於沒排到——人家公司沒人，業務自己也在放假。
所以排下次聯絡日、設回撥提醒時會自動跳過不上班的日子。

- **會自動順延**：下次聯絡日的快捷鍵（明天、3 天後、一週後…）、**自己用日期框挑的
  日期**、從訪談內容自動抓出來的日期（「約下週三再打」）、回撥提醒的「自訂時間」
  （時間點留著，只換日期）。順延時一定會講原因：「2026/09/25 是中秋節，順延到
  2026/09/29（二）」。
- **不會自動順延**：只有「今天」——人就是在今天按的。
- 日期框是在 `change`（挑完、關掉日期選擇器）才順延，不在 `input` 時動：邊打年份邊
  被改會很煩。改完再送一次 `change`，草稿那些才會存到順延後的日期。

> 一開始自己挑的日期是照留的，只在旁邊標一行「⚠ 國慶日（放假）」。使用者說不用留，
> 挑到假日就直接跳到下一個上班日——反正那天打不到人。
- 連假整串跳過：一天一天往後找，所以春節九天、中秋接教師節這種都會跳到真正的上班日。

`assets/js/holidays.js` 是政府行政機關辦公日曆表（人事行政總處公告）的整理版，
只存兩種特例：平日放假（國定假日、補假、彈性放假）與週末補班。週六日本來就不上班，
不用一天一天列。目前涵蓋 2025–2027，**每年年底公告隔年行事曆時要補一年進來**；
沒有資料的年份不猜，只避開週末，日期提示也會寫明「2028 年行事曆還沒更新，只避得
開週末」——不能讓使用者以為網站已經幫他避開國定假日了。

## 預設排序：最近核准變更（新到舊）

剛增資、剛換負責人、剛搬家的公司排在最前面，那是最值得打的一批。下次聯絡日那條線
有提醒列在顧，不需要再靠排序。

## 關係企業共享電話與「有沒有機會」

手動連結成同一個老闆的公司，本來就連動下次聯絡日、最近聯絡日與撥打狀態。再加兩樣：

- **電話**：自己沒號碼的那家借同組有號碼的來用，旁邊標明「這家自己沒有電話，上面的
  號碼是同老闆的『○○』的」——不講的話打過去會說錯公司名。自己有號碼的一律用自己的，
  那才是這家的總機。借到號碼就不算「無電話」，不然它會一直待在「要補電話」的名單裡，
  可是根本補不到也不需要補。
- **有沒有機會**：老闆說「願意給資料評估」講的是他自己，不是某一家公司，所以整組共用。
  改過主意就以**最後標的那一次**為準（比 `chanceAt`，跟雲端合併同一套規則）；詳細頁會
  寫明「是跟著同老闆的『○○』」，按鈕的亮暗則看這一家自己標了沒。

跟日期連動一樣，這些都只影響顯示、篩選與排序，**不改任何一家存起來的資料**——解除
連結就各自回到原樣。

### 「最近核准變更」後面接上查到什麼

只放一個日期的話，看的人還是得往下捲到「變更登記」才知道公司到底動了什麼。所以那
一列後面接一句摘要：

```
最近核准變更   2026/09/20　查到增資：資本總額（仟元） 150,000 → 160,000
```

用「查到」而不是把變更直接寫成那個日期發生的事，是因為那個日期是**政府登記的核准
日**，跟網站查到差異的那天未必是同一天。完整清單（每個欄位前後值、查到的日期、最近
查核日）仍然在下面的「變更登記」。

## 複製鈕＝一顆灰點

名單上每張卡片、每支電話後面都跟著一顆「複製」，兩個字比電話號碼本身還搶眼。改成
一顆 10px 的灰點（本來是綠色，但卡片上已經有綠色的優先區域、有機會、分公司標記，
複製只是輔助動作，不該跟那些搶顏色；滑過去、按下去才變深）：

- **點的大小跟著旁邊的字走**：直徑就是那行字的一半（`0.5em`）。公司名稱那顆大、電話與
  統編那顆小，看起來才是同一個東西的不同尺寸，而不是隨便擺一顆固定大小的點。垂直位置
  對齊那行字的中線（`vertical-align: 0.1em`，實測校出來的）。
- **按的範圍另外用 `::after` 疊一塊透明區**，約 29×31，手指按得到；按鈕本身只有 1em 高，
  塞在文字行裡不會把行距撐開。這塊透明區**往右與上下擴、左邊只留 3px**：左邊就是電話
  膠囊或那串數字，整圈擴出去會蓋到它們——在手機上想按撥號結果按到複製。
- 文字移到 `aria-label` 與 `title`：讀螢幕的人聽得到「複製電話 0211111111」，滑鼠
  滑過去也看得到。
- 按成功那顆點會**擴一圈再收回來**。沒有文字了，按下去如果畫面完全沒反應會讓人懷疑
  到底有沒有複製到——提示訊息在畫面最下面，眼睛未必跟過去。

有點的地方：每一支電話、公司名稱、**統一編號**。統編查商工登記、貼進公司系統都用得到，
手打八碼很容易錯。三處共用同一個 `copyDot()`，行為一致（同樣的閃一下、同樣不會誤開
詳細頁）。

設定視窗裡的「複製腳本」維持原樣：那是一次性的動作，旁邊就是一大段程式碼，換成一顆
點會看不懂要做什麼。

### 順手修掉：`aria-label` 一直沒生效

`el()` 原本整包丟 `Object.assign`，`node['aria-label'] = x` 只是在物件上掛一個沒人
看得到的欄位，屬性根本沒進 DOM。這種錯不會有任何訊息，就這樣靜悄悄地失效——讀螢幕
的人什麼也聽不到。改成帶連字號的鍵走 `setAttribute`，`aria-*`、`data-*` 都跟著修好。

## 存不進去要講出來

使用者回報「剛儲存訪談紀錄，結果沒存到」。看程式碼才發現：`儲存紀錄` 那段完全沒有

紀錄也沒存到，使用者只會以為自己沒按到按鈕。

現在：

- 寫入包在 `try` 裡，失敗就顯示「存不進去：<原因>。內容還留著，先複製起來，重新整理
  再試一次。」
- **寫完讀回來確認**那一筆真的在資料庫裡（比對 `createdAt`），寫得進去卻讀不回來也
  算失敗——不然畫面說「已儲存」但東西不在，比直接報錯更糟。
- 失敗時**不清空輸入框、不清掉草稿**，內容不會被吃掉。
- 修改與刪除紀錄也補上同樣的處理。

## 往來情形整組一致

使用者回報「關係企業的往來狀態沒有連動」。重現出來的樣子是：同一組兩家，**同一天各

原因：每一家都是拿「自己＋同組」的訪談合起來判讀，但**判讀只看最新一則**，而合起來

## 往來情形：分公司名稱也算中租

業務在紀錄裡寫的是「城東202210結束」「融專目前億土建榮」「宜花已經沒」——不會寫成
「中租城東分公司」。所以中租單位的名單加上**行銷區域劃分表上的所有分公司名稱**
（城中、城東、城北、新莊、新北、桃園、新竹、宜花、北台中、南台中、中彰、彰化、嘉義、
府城、台南、北高雄、南高雄、高屏），以及名單裡看到的「供型／弓形」兩種寫法。

判定規則：**同一小句裡有中租單位 ＋ 本餘或往來字眼（往來、承作、配合、合作、進件、
有案），而且沒有否定字**，就算「有跟中租往來」。原本一定要有「還在／目前／有」這種
前綴才算，但「城東8000萬往來中」「新北承作設備案」沒有前綴，照樣要算。

**同名的地址與銀行要擋掉**：分公司名稱有一半同時是地名或銀行名，後面接
「市、縣、區、鄉、鎮、路、街、號、樓、銀行、商銀、分行」就不算中租單位——不擋的話，
光是地址出現在訪談內容裡（「公司在新北市新莊區…」）就會被判成跟中租往來。
「往來對象」那邊也套同一個防呆。

剩下一個沒辦法自動分辨的：**「彰化」單獨出現**（沒接「銀行」）會被當成彰化分公司。
真的要指彰銀的話，紀錄裡寫「彰銀」或「彰化銀行」就不會誤判。

**合迪算中租，不算同業**：合迪是中租集團的公司，原本放在同業清單裡（台新租賃、
中國租賃、和潤、裕融、新鑫、遠信、博鈞）是錯的。現在「合迪本餘 300 萬」「跟合迪
還在往來」都算有跟中租往來，「往來對象」那邊也從「同業」改列「中租其他單位」。

## 存不進去要講出來（第二輪：關係企業連結）

使用者回報「把兩家建立關企，但它儲存失敗」。跟通話紀錄那次一模一樣：`儲存連結`
那段也沒有 `try`，`Store.setState()` 被瀏覽器擋下來就是一個沒人看得到的 unhandled
rejection——視窗收掉、什麼都沒存到、畫面一句話都沒有。

- 寫入包在 `try` 裡，失敗顯示「連結沒存起來：〈原因〉。視窗留著，再按一次試試看。」
- **視窗不收掉**：收掉就等於告訴使用者存好了。
- 寫完**讀回來確認每一家都連上**（連結是靠每一家各自存 `group` 欄位串起來的，少存到
  一家就等於沒連上）。

### 還加了一層網子

逐一補 `try` 是對的，但漏掉一條就再來一次。所以掛上 `unhandledrejection`：沒人接住的
失敗會跳一行「有個動作沒完成：〈原因〉。請重新整理再試一次。」，細節照樣印在主控台。
這樣就算還有沒補到的路徑，至少不會再靜悄悄地失敗。

## 刪掉又「自己跑回來」

使用者回報刪了一筆客戶，它一直回到名單上。查下來有兩條路會造成這個現象，兩條都處理了：

**一、同一家公司在好幾份名單裡各有一筆。** 客戶的 id 是「檔名＋公司名＋統編」算出來
的，所以同一家出現在兩份名單就是兩張各自獨立的卡片。只刪掉眼前這一筆，另一份名單那
筆還在——看起來就像刪掉又跑回來。現在刪除時會先查有沒有同一家（有統編比統編，沒有比
公司名），有的話問一次：

> 名單裡還有 1 筆同一家公司（來源：B名單-20260901.csv）。要一起刪掉嗎？
> 按「確定」全部刪掉；按「取消」只刪剛才那一筆。

**二、刪除本身失敗但沒人講。** 跟通話紀錄、關係企業連結同一個老問題：`deleteRecord()`
沒有包 `try`。現在失敗會顯示「刪不掉：〈原因〉。請重新整理再試一次。」，而且**刪完會
讀回來確認**那幾筆真的不在資料庫裡。

至於雲端同步：墓碑機制本身是對的（實測刪除後跟舊的雲端版本合併，不會被救回來）。
**唯一會回來的情況是另一台又匯入了同一份名單**——那是使用者自己重新匯入的，不是同步
出錯，刪除確認視窗裡本來就有講。

## 新增客戶時擋掉重複的公司

同一家公司出現兩張卡片，兩張各自記通話、各自排下次聯絡日，等於打兩次。所以「新增
客戶」那邊在存之前先比對名單：

- **手動新增**：找到同一家就**不新增**，改問「要打開既有的那一筆嗎？」，並附上它在哪
  一份名單、最近聯絡與下次聯絡日。按確定直接跳過去，按取消留在表單繼續改。
- **貼上整列**：已經在名單裡的**自動略過**，提示寫「已新增 3 筆，略過 1 筆已經在名單
  裡的（大塊系統工程股份有限公司（已在A名單-20260917.csv））」。整批裡自己重複的也只
  留一筆。

比對方式：**有統編比統編**（唯一且沒有寫法差異），沒統編才比公司名稱（去掉空白）。
原本只擋「一模一樣的 id」，而 id 是「來源＋公司名＋統編」算出來的——同一家已經在 A
名單裡的話，手動新增會算出不同的 id，就這樣多出一張卡片。

（檔案匯入那條路本來就會問「覆蓋／並存／略過」，不走這裡。）

## 剛連好的關係企業自己不見了

使用者連了兩家公司，畫面顯示成功，回頭看卻變回「這家還沒連結其他公司」。

**根本原因是「整列覆寫」＋「舊副本」。** 追蹤狀態（`state` 這張表）是一筆客戶一列，
每次寫入都是整列覆寫；`saveState()` 原本拿**記憶體裡的副本**當合併底稿。可是同一列
會有好幾個人寫：

- 背景的商工登記更新（每一筆都會寫查核時間 `regAt`）
- 另一個分頁
- 同步完成後的重載

只要有人拿著「連結之前」的副本整列寫回去，剛寫進去的 `group` 就這樣沒了——而且完全
無聲，因為那次寫入本身是成功的。

改法：`saveState()` 合併前先讀**資料庫裡當下那一列**（新增 `Store.getState()`），
讀不到才退回記憶體那份。多讀一次 IndexedDB 很便宜，正確性比較重要。

順手修掉連結視窗一個讓人以為沒勾到的行為：**勾起來的公司原本會從清單消失**（清單把
已勾的濾掉了），一打字搜尋就整列不見，只剩上面的小標籤。現在勾了還留在清單上，而且
是勾著的狀態。

## 刪掉的公司，下一份名單不要再帶回來

名單是一份一份拿到的，同一家公司會在好幾份裡重複出現。刪掉一次，下個月的新名單又把
它帶回來，等於每個月要重刪一次同一家。

刪除時除了原本的 id 墓碑，現在另外記一張**公司墓碑**：統編一張、公司名（去掉空白）
一張。兩張都記，是因為同一家公司可能這份名單有統編、那份沒有，只記一種就會漏。匯入
時只要中一張就不匯進去。

為什麼原本的墓碑擋不住：客戶的 id 是 `檔名＋公司名＋統編` 算出來的雜湊，**換一份名單
就換一個 id**，所以 id 墓碑只擋得住同一份名單裡的同一筆。

**每一條加客戶的路都會剔除**：檔案匯入（PDF／CSV／Excel、經濟部登記清冊）、104 截圖、
貼上整列、手動一筆一筆新增。只擋匯入那一條的話，一家已經決定不要的公司還是會從別條路
溜回名單上。

手動新增是唯一會**問一次**的：使用者是一個字一個字打進來的，悶著不動只會以為網站壞了。
講清楚「先前刪掉、已經設成排除」，預設不新增；真的要就按「還是要新增」，那時才把排除
收回（不收回的話下次匯入又會被自己的墓碑擋掉）。

**一定會講出來**：匯入記錄寫「排除 2 筆你先前刪掉的公司（甲工程有限公司、乙精密…）」。
無聲的擋掉比不擋還糟——使用者會以為是匯入壞了。

**收得回來**：⋯選單 →「管理已排除的公司」列出目前排除的公司，點一家就收回，之後匯入
會照常出現。公司墓碑也會跟著雲端同步，在電腦上刪掉的，手機匯入名單時一樣擋住。

收回**不是把鍵刪掉**，而是寫一筆比較新的「已收回」標記。墓碑同步是聯集合併，直接刪
的話下一次同步雲端那份又會把它加回來——收回等於沒收回，而且完全無聲。

### 這個功能上線前刪掉的也算

舊的刪除只留下 id 墓碑，而 id 是雜湊，**反推不回公司名**。但可以正推：id 是
`makeId(來源檔名, 公司名, 統編)`，公司名和統編就在新名單的列上，來源檔名則是手上有過
的那幾份。匯入時把每一家配上每一個來源各算一次，對得上舊墓碑就是同一家。

認出來之後會順手補一張公司墓碑，所以下次不必再重算，也才列得進「管理已排除的公司」。
統編帶與不帶各算一次，涵蓋「舊名單有統編、新名單沒有」這種情形。

## 刪除按了沒反應

使用者回報「我剛刪除這筆，但為什麼還讀得到他的資訊」：畫面上那筆還開著，刪除鈕還留著
點過的外框，就是沒刪掉。

不是資料庫的問題。Chrome 只要同一個頁面連續跳出兩次對話框，就會多一個「不要再讓這個
網頁建立對話方塊」的勾選；勾下去之後，**後面每一次 `confirm()` 都直接回傳 false，
而且不會有任何畫面**。對刪除來說就是按了沒反應，完全無聲。刪除同一家公司的重複那筆時
會連問兩次，正好踩在這個條件上。

所以網站裡的 `confirm()`、`prompt()`、`alert()` 全部換掉，改成自己畫的確認框
（`askConfirm` / `askPick`）。它是頁面裡的一個 div，瀏覽器管不到，手機上也比原生對話
框好按。順帶把按鈕字改成在做什麼——「刪掉」「全部刪掉／只刪這一筆」「清空」，比「確定
／取消」清楚。

「管理已匯入名單」原本要把檔名一字不差打出來（打錯就當作取消），現在直接列成按鈕。

## 儲存訪談紀錄失敗，而且重打一次還是失敗

**根本原因是資料庫連線被收掉之後沒有重開。** `store.js` 開啟 IndexedDB 之後把連線
快取起來用到分頁關掉為止。但瀏覽器會自己把它收掉——手機把網站擱在背景一陣子、系統
回收資源、另一個分頁要升級資料庫，都會。收掉之後每一次 `db.transaction()` 都丟
`InvalidStateError`，而快取裡還留著那條死掉的連線，所以**「存不進去」會一直持續到
使用者自己重新整理為止**，重打一次當然還是失敗。

改法：連線斷了就把快取丟掉、重開再試一次。重試是安全的——IndexedDB 的交易是全有
全無，中途失敗一定整個回捲，不會留下寫到一半的東西，所以同一批動作再做一次不會變成
兩筆。另外掛上 `onclose` / `onversionchange`，連線一斷就主動丟掉快取；開啟失敗的
promise 也不再留著（留著的話之後每一次呼叫都拿到同一個失敗）。

順手修掉三件會讓人白打一次的事：

- **兩次寫入分開報。** 通話紀錄（logs）和追蹤狀態（結果、下次聯絡日）是兩次寫入，
  以前包在同一個 try 裡，第二次失敗也講「存不進去」——可是紀錄其實已經存好了，
  照著訊息重打一次就變成兩則一模一樣的。現在講明「紀錄已存好，但結果與下次聯絡日
  沒寫進去」。
- **存檔中不能再按。** 按鈕在寫入期間變成「儲存中…」並停用，連點兩下不會變兩則。
- **失敗原因留在畫面上。** toast 兩秒多就消失，錯過就不知道發生什麼事；現在表單上
  多一行紅字寫明原因，並且講「你打的內容還留著，直接再按一次就好」。
- **草稿多一層記憶體備份。** 草稿原本只存 localStorage，而它會失效（無痕模式、空間
  滿了、隱私設定）且完全無聲，一失效打到一半的字在下一次重畫就沒了。

## 連結其他公司：打名字就從商工登記抓進來

原本「連結其他公司」只能從**已經在名單裡的公司**勾。可是關係企業常常根本不在名單上
——那家沒有出現在任何一份開發名單裡，於是要嘛連不到，要嘛得先切出去手動新增一筆、
統編地址一個一個打，再回來連。

連結視窗底下多一區「名單外的關係企業」：**知道是哪一家就直接打公司名**，按一下（或按
Enter）去商工登記查，把符合的公司列出來，勾了存檔就連同統編、負責人、資本總額、地址
一起加進名單並連結，來源標「商工登記」。

**網站不猜、也不幫忙找關係企業。** 欄位預設是空的——是使用者自己知道那家是關企才打
名字進來的，網站要做的只是省下手打、並且確保抓到的是登記上的正確資料。查到的每一家
仍然列出來按一下確認（同名或名字相近的公司是有的），統編、負責人、地址擺出來，勾哪一家
由人決定。每一家都標示在不在名單裡：

- **已在名單**：寫明在哪一份名單，勾了就連結
- **名單裡沒有**：勾了會一起加進名單再連結
- **就是這一家**：自己那一筆，勾不動

加進來的公司一樣吃排除名單——自己刪掉過的公司不會從這裡溜回名單上，被擋掉會講。

**打統編也可以**：輸入的是純數字 8 碼就改用統編查（名稱一字之差就查不到，有統編時
這條最準）。

### 不要自己另外組一條查詢網址

第一版這裡自己組了一份幾乎跟「用名稱查」一樣、但 `$top` 從 5 改成 50 的網址，想說
「使用者可能只打得出前幾個字，多拿幾筆」。結果使用者的代理兩種寫法都回**查無資料**，
而同一台裝置的商工登記更新明明是好的——差別就只在那個自己加的參數。

現在直接呼叫 `Registry.lookupByName()` / `lookupByTaxId()`，也就是網站每天在用的那兩條，
一個參數都不改。查同一份資料就走同一條路，不要為了「想多拿幾筆」另外開一條沒人驗過的。
（測試會逐字比對查詢網址跟 `officialByName` 產生的一模一樣，並且斷言 `$top` 還是 5。）

### 查不到會自己退一步，而不是把「查無資料」丟回去

`like` 要對得上登記上的寫法，而登記全名常常跟業務講的差幾個字（「方舟國際股份有限公司」
實際登記是「方舟國際**開發**股份有限公司」）。所以查不到會自己往下試：

1. 使用者打的全名
2. 去掉組織型態的短名（`companyStem`：「方舟國際股份有限公司」→「方舟國際」）
3. 欄位最齊的那支資料集（應用一）也用名稱試一次——平常它只拿來用統編查，但關鍵字
   查詢那支在某些代理上就是回空白，多一支多一條路

用短名查到時會講「（用「方舟國際」查到的）」，不讓人以為全名就是登記上的寫法。

**全部落空時把每一次查詢的網址列出來讓使用者點開。** 連結指向政府網站本身而不是代理，
繞過代理才分得出是誰的問題（有 JSON 就是代理的問題，空白就是真的查不到）。

### 分得出「這個名字比不到」還是「用名稱查整條路不通」

使用者卡住的就是這個：**統編更新天天成功，名稱卻一直查無資料**。兩者走的是**不同的
資料集**（統編用「應用一」`7E6AFA72`，名稱用「關鍵字查詢」`5F64D864`），所以統編那條
好好的完全不代表名稱這條也好。而既有的「先試一筆」探測是拿**統編**去試的，對這件事
永遠回答「通」，一點忙都幫不上。

所以加了 `probeNameQuery()`：查不到時自動拿一家一定存在的公司走同一條路試一次，然後直接
講結論：

- **查得到** → 「用公司名查是通的。所以是這個寫法在登記上比不到——最常見的原因是打了
  簡稱，也可能是登記全名多幾個字或狀態不是『核准設立』。改用統一編號最準。」
- **查不到** → 「用公司名查整條路不通……（統編那條是另一支資料集，那支是好的。）
  兩條路可以走：按下面的 g0v 鏡像，或改用統一編號。」

### 探路用的公司名一定要是登記全名

第一版把探路的名字寫成 **「台積電」**——那是簡稱，登記上叫「台灣積體電路製造股份有限
公司」，資料庫裡根本沒有哪一家的名稱含「台積電」三個字。拿它去比對**必然**查無資料，
於是探測每次都回「不通」，畫面跟著下了「用公司名查整條路不通」這個**假結論**，害使用者
以為要去換資料集、白白試了好幾輪。

探路的東西本身查不到，測出來的就只有它自己。現在改成登記全名
`台灣積體電路製造股份有限公司`（`nameVariants` 會連「臺」那版一起試）。

同一件事也是使用者查不到的最常見原因，所以直接寫進畫面與欄位提示：**登記比對的是全名，
簡稱查不到**——「台積電」要打「台灣積體電路製造股份有限公司」。

順手補上 `officialByName` 一直寫在註解裡、程式卻沒做的事：**`like` 之後再試 `eq`**。
原本兩個「寫法」都是 `like`，萬一這支資料集的 `like` 不吃中文或已經不支援，`eq` 是另
一條路。

**刻意沒有做「用負責人姓名找同一個人名下的公司」**：那要拿 `Responsible_Name` 當
`$filter` 條件，而這支資料集接不接受，開發環境連不上政府網站（`data.gcis.nat.gov.tw`
被擋）驗不了，不想為了一個驗不了的東西多一個會靜靜失效的路徑。

查不到時把**每一種寫法**的結果照實列出來：名字打錯、代理不通、資料集有問題，三件事的
處理方式完全不一樣，不講清楚只會亂試一通。而且「查無資料」會順便講怎麼改——少打幾個字
或改用統編，不然使用者只會對著同一個名字一直按。

### 「查無資料」不能把實際收到的東西吞掉

`unwrap()` 對「不是陣列、也不是 `{data}`／`{company}`」的 JSON 一律回 0 筆——政府端回的
錯誤物件（`{"Error":…}`）正好長這樣，結果畫面只寫「查無資料」，那句真正的訊息被整個
吞掉。使用者回報「打公司名一直查不到」卡了好幾輪，就是因為看不到那句話。

現在 0 筆時也會把實際收到的內容（Content-Type ＋前 300 字）掛在結果上，畫面照樣印
「實際收到：…」。改法是把附註掛在回傳的陣列上，不影響任何現有的呼叫端。

### 還有一條路：g0v 社群鏡像

官方那支名稱查詢不通時，g0v 鏡像常常查得到——它不是 OData，是社群維護的同一份登記
資料、有自己的搜尋。但它是第三方，照既有的做法**不預設偷偷送出去**：查不到時給一顆
「改用 g0v 社群鏡像再查一次」的按鈕，並且講明送出去的只有公司名。查到的結果會標明
來源是鏡像、提醒勾之前看一下統編。

### 結論放前面，一長串嘗試收起來

使用者連續好幾輪對著一長串「查無資料」試不同的名字——**那串東西對他沒有用**，他要的是
「那我現在該按哪裡」。而且實測結果是：他那邊連**台積電**、連**另一支資料集**都查不到，
也就是用公司名查整條路在他的環境是死的，再怎麼換名字都一樣。

所以查不到時的畫面改成：

1. **結論**（跑完台積電探測才印）：「用公司名查整條路不通……兩條路可以走：按下面的
   g0v 鏡像，或改用統一編號。」
2. **可行的那條**：g0v 鏡像按鈕
3. **查詢明細**收進可展開的 `<details>`，裡面才是每一次嘗試的原因、實際收到什麼、
   可點開的政府網站網址

明細裡多一顆**「複製診斷內容」**：版本、探測結果、每一次嘗試與實際收到的內容一次複製。
在手機上要逐段選取那串東西才貼得出來問人，這顆按鈕省掉的就是那一步。

### 公司名跟統編黏在一起貼進來也要認得

判斷「這是統編嗎」原本的條件是**整串**扣掉空白和 `-` 之後剛好 8 碼數字。結果使用者照著
畫面提示（「登記全名或統一編號」）把兩個一起打進來——`台灣積體電路製造股份有限公司22099131`
——整串就被當成公司名去查，當然查無資料，而那串裡明明有一個可以直接查到的統編。
從試算表複製一列貼上也會長這樣。

改成**從輸入裡把 8 碼數字挑出來**：先用統編查（最準），剩下的字才當公司名，順手把黏在
頭尾的分隔符號去掉。查不到時也會講「你貼的統編 ⋯ 也查過了，一樣沒有」，免得使用者以為
統編那段被忽略了。

### 字串值要不要加單引號

使用者那台的症狀很特別：**用統編查天天成功，用公司名查永遠查無資料**——連登記全名
「台灣積體電路製造股份有限公司」、連它的前綴「台灣積體電路」都一樣，換資料集、換寫法、
按 g0v 鏡像都沒用。

兩者唯一的差別是**值是數字還是字串**：

```
Business_Accounting_NO eq 22099131          ← 數字，不用引號，一直通
Company_Name like 台灣積體電路製造股份有限公司  ← 字串，沒加引號，一直空
```

OData 的字串值本來就要用單引號包起來（`Company_Name eq '台積電'`），只是商工平臺的
文件範例寫的是不加引號的 `like`。哪一種才對沒辦法在開發環境驗證（連不上政府網站），
所以**兩種都試**，文件上的寫法擺前面（真的能用就不必多打幾次），加引號的當備援：

```
Company_Name like X and Company_Status eq 01     （文件寫法）
Company_Name like X
Company_Name eq X and Company_Status eq 01
Company_Name eq X
Company_Name like 'X' and Company_Status eq '01' （加引號）
Company_Name like 'X'
Company_Name eq 'X'
```

台／臺兩種寫法各一輪，所以名稱查詢一共 14 條；應用一那支備援也跟著加上加引號那種。

g0v 鏡像的搜尋端點也改成兩種形式都試（`/api/search/<名稱>` 與 `/api/search?q=<名稱>`）
——`/api/show/<統編>` 是 path 形式，但鏡像按下去一樣查不到，那搜尋很可能是 query 參數
那種。猜不出來就兩種都打一次，失敗照實列出來。

「複製診斷內容」也把**每一次送出的網址**一起複製：光看「查無資料」看不出送出去的是哪
一種寫法。

### 分得出兇手是資料集還是查詢條件

「用公司名查不到」有兩個完全不同的原因，而先前做的探測**都分不出來**：

- `probeDataset` 拿統編去試，但它打的是「用統編查」那幾支資料集——那幾支本來就是好的，
  所以它永遠回答「通」
- `probeNameQuery` 拿公司名去試，失敗時分不出是資料集死了還是查詢條件的問題

`probeBaseWithTaxId()` 才分得出來：用**名稱查詢那支資料集**（`getBase()`），但條件換成
**統編**（純數字）。資料集一樣、代理一樣，只有「值是數字還是中文」不同，所以結果直接
指出兇手：

- **查得到** → 這支資料集活著、篩選也能用，**是它不吃「用公司名查」這個條件**。
  不是使用者打錯名字，換幾個名字都一樣。
- **查不到** → 這支資料集整支不通，編號可能已經失效（每日更新走的是另一支，所以沒受影響）。

兩種情況都直接給現在可行的做法：① 直接貼統一編號 ② 按 g0v 鏡像；要修才去換資料集網址。

### 查不到也不要把人卡住

使用者知道那家是關企、名字就在眼前，只是商工登記查不到而已。與其要他切出去手動新增
一筆再回來連，不如多一顆**「直接用『◯◯』加入並連結」**：用他打的名字建一筆直接連上，
統編與資本額之後自己補（輸入裡有 8 碼數字的話會一起帶進去）。少了登記資料的那一筆，
總比連不起來好。

### 查到的就是自己時，不要畫成「已勾選」

使用者貼了統編，查到了那一家，畫面卻給他一個**藍色勾勾**配「就是這一家」，而且勾不動。
實際回報是：「這是什麼狀態，我還沒建立連結耶」。

勾勾在這個畫面的意思是**「會連結」**，拿它來表示「這是你自己」等於講了反話。改成：

- 那一列**不放核取方塊**，直接寫「這就是你正在看的這一家（統編一樣），不是關係企業——
  請改打關係企業那一家的名稱或統編」
- 如果查到的**全部**都是自己，上面的提示也換掉，不要還寫「勾你要的那一家」——那只會
  讓人以為畫面壞了
- 已經在名單裡的那種，標籤補上「勾了就連結」，講明勾勾是做什麼的

### 連結關係企業改成先打 g0v 鏡像

使用者那台的「用公司名查」官方整條不通（連登記全名都查無資料），但 **g0v 鏡像查得到**
——台積電的統編、負責人、資本總額、地址全抓回來了。他的要求很直接：「請都用 g0v 查詢」。

所以這個畫面改成 `mirrorFirst`：**鏡像排第一**，鏡像沒有才往官方／代理要。原本是官方
先跑 14 種寫法、全部落空才落到鏡像，等於每次都先卡十幾秒。那顆「改用 g0v 社群鏡像再查
一次」的按鈕也就不需要了。

鏡像的資料不是政府即時的，所以結果那一行會註明來源是 g0v、提醒勾之前看一下統編；加進
名單之後每天的商工登記更新（走統編、官方那條）會自己把資料校正回來。

**沒有公司名稱的那幾筆不列出來。** 鏡像的搜尋結果混著公司、商號、分公司，欄位名稱各不
相同，對不上就變成「（無名稱）統編 98270490」這種只有統編的列——勾了也不知道是什麼公司。
名稱欄位先多補幾個候選（`Branch_Name`、`分公司名稱`、`名稱`），剩下真的沒有的就略過，
並在提示裡講「另有 N 筆沒有公司名稱，略過」。

### 查到的那一列直接按一下就完成

原本的流程是：查到 → 捲下去勾核取方塊 → 再捲到視窗最底按「儲存連結」。使用者的話很
直白：**「別再讓我跳到下面去勾選，白忙一場」**。而且那顆按鈕本來就寫著「查商工登記
**並加入**」，卻只查不加入，等於說了不算。

現在查到的每一列右邊直接給一顆按鈕：

- 名單裡沒有的 → **「加入並連結」**
- 已經在名單裡的 → **「連結這一家」**

按一下就把它加進名單、連結、存檔、關掉視窗，一次做完。查不到時那顆「直接用『◯◯』加入
並連結」也一樣，按下去就做完，不再要人捲到下面。

結果列還會自動捲進畫面（`scrollIntoView`）——它常常落在畫面外，使用者會以為按了沒反應。

## 把今天該打的平均分散到接下來的工作天

名單匯進來時下次聯絡日常常擠在同一天（或整批逾期），一早打開看到一百多家，實際上一天
打不完，剩下的又全部變成逾期，隔天更多。業務要的是「把這批攤平到接下來兩三週，每天固定
打幾家」。

⋯選單 →「**把今天要聯絡的分散到未來 15 個工作天**」。按下去會先問一次，並把要發生的事
講完整：

> 今天要聯絡的有 30 家（其中 10 家已逾期）。
> 要把他們的下次聯絡日平均分散到接下來 15 個工作天嗎？
> 2026/09/22 ～ 2026/10/15，每天最多 2 家。
> 逾期越久的排越前面。週末與國定假日會跳過。
> 原本的下次聯絡日會被蓋掉（可以馬上按選單裡的「復原剛才的分散」還原）。

幾個刻意的決定：

- **對象是「下次聯絡日 ≤ 今天」**，也就是今天到期＋已經逾期的。只算今天那一天的話，
  逾期那堆還是躺在那裡，問題沒解決。
- **禁止推廣的不排**：那是判定過不再打的，排進來只會每天看到它。
- **逾期越久的排越前面**（照原本的下次聯絡日排序），分段切給每一天，不是隨機灑——
  最該打的還是最先打。每天的家數相差不會超過一家。
- **只落在工作天**：跳過週末與國定假日（補班日算工作天），用的是既有的台灣行事曆。
- **改得回來**：這是一次蓋掉幾十筆日期的操作，所以把原本的日期留在記憶體裡，選單會多
  出「復原剛才的分散」，按一下全部還原。（只在這次開著的網站裡有效，關掉就沒了——
  所以那句話寫在確認框裡。）

## 密碼鎖

網址分享出去就收不回來。使用者把連結給了同事之後反悔，所以進站前加一道密碼。

**先講清楚沒有外流的部分**：名單只存在各自的瀏覽器（IndexedDB），網址不帶任何資料；
雲端同步用的是**各自的 Google 帳號**、存在**各自的雲端硬碟**裡（scope 是 `drive.file`，
只碰得到這個程式自己建的檔案）。所以拿到網址的人打開看到的是一個**空的網站**。

### 這是門檻，不是帳號系統

這是純前端的靜態網站，原始碼在 GitHub 上是公開的，所以：

- 密碼**絕對不能**明文寫進程式裡——只放 PBKDF2-SHA256 的雜湊與鹽，迭代 25 萬次，
  讓離線暴力猜密碼慢到不值得
- 即使如此，懂技術的人還是可以把這段跳過。**但跳過之後看到的仍然是一個空的網站**
  （資料在本機、不在網址裡），所以這不是漏洞，是門檻——擋的是不請自來的人
- README 裡把這一點寫明，不要讓人誤以為這是帳號系統

### 兩個實作上的選擇

- **解開之後記在這台裝置**（localStorage 存雜湊值），手機、電腦各輸入一次就好
- **本機（localhost／`file:`）不鎖**。要擋的是分享出去的那個網址；在自己電腦上跑沒有
  這個問題，而且原始碼本來就公開，任何人都能自己跑起來，鎖本機沒有多擋到誰，只會讓
  每一支自動測試都卡在門口。網址帶 `?lock=1` 就照鎖，這道門本身才測得到。

要換密碼就換 `assets/js/lock.js` 裡的鹽與雜湊（用 PBKDF2-SHA256、25 萬次、32 bytes）。

## 調整回撥時間一直失敗

按鈕上的時間**在詳細頁畫出來的那一刻就定下來了**，不是按下去的那一刻：

```js
b.onclick = at(Date.now() + 60 * 60000);   // render 時就算好了
```

實際的使用方式是：打開詳細頁 → 講電話 → 講完才按「1 小時後」。於是設進去的是「**開頁面
之後一小時**」，早就過了；畫面照樣顯示「該回撥了」，看起來就是「調整一直失敗」。

整點按鈕更明顯：那串清單是 render 當下過濾掉過期時段的，頁面開著放到 11 點之後，
`11:00` 還留在上面可以按，按了就設進一個過去的時間。

改法：

- **時間一律在按下去的那一刻才算**（把 `at(ts)` 從「算好再綁」改成「按下去才算」）
- **整點按下去時再確認一次**：已經過了就改設**明天同一個時間**（撞到假日順延到下一個
  上班日），並講明「今天 11:00 已經過了，改設 2026/09/22 11:00 回撥」
- **自訂時間選到過去就擋掉**：「09:00 已經過了，請選一個之後的時間」。設進去馬上就是
  「該回撥了」，跟沒設一樣
- `setReminder` 補上 try/catch：存不進去要講出來，不然畫面上的時間動都不動，使用者
  只會覺得「調整一直失敗」

## 詳細頁單筆匯出 Excel

要把一家客戶的資料交出去（給主管、給徵信、貼進別的表）時，整份名單匯出來再自己刪到剩
一列很花時間，而且**容易連別家客戶的資料一起送出去**。所以詳細頁的按鈕列多一顆
**「匯出 Excel」**，只匯出眼前這一家。

格式**沿用整份匯出那一套**——同一個 `exportXlsx()`，只是多收一個「要匯哪幾筆」的參數。
不另外寫一份，免得兩邊哪天走鐘：欄位、黃底表頭、框線、民國年的訪談內容、列高都一樣，
所以拿到的檔案跟平常的母檔長得一模一樣，改完還能直接拖回網站。

檔名是 `公司名稱_2026-09-21.xlsx`；公司名裡的 `\ / : * ? " < > |` 會換成底線，不然某些
系統存不了檔（公司名常有括號、斜線）。

### 匯出要跟畫面一致：同老闆的訪談與電話也要帶

第一版的單筆匯出把「訪談內容」整格空著送出去。原因是匯出讀的是**這一筆自己的欄位**，
而詳細頁顯示的是**同老闆整組合起來**的結果：

- 像「星彩實業」這種自己一則訪談都沒記、全都記在同組「星焱實業」上的公司，匯出來就是
  空的——可是使用者畫面上明明看得到
- 電話同理：自己沒號碼時畫面顯示的是同組借來的那支，匯出也是空的

改成用 `notesBundle()`（時間軸用的同一份）組訪談內容，電話沒有自己的就帶借來的那支。
借來的那幾則**標上是哪一家的**：

```
115/09/21 03:40 [已聯絡]（星焱實業股份有限公司） 董小姐說下週三再談
（星焱實業股份有限公司）2026/09/10 母公司這邊談過
02-26032200 分機619（星焱實業股份有限公司）
```

標出處有兩個理由：業務照著打過去才不會講錯公司名；而且這個檔案可以再拖回網站，不標的話
別家的紀錄會被當成這家自己的。

## 無法更新訪談紀錄

使用者按「修改」改完內容，畫面跳「已更新這則紀錄」，但內容沒變。

**兩個問題疊在一起：**

1. **`logId` 同步過後會重新編號。** 那是 IndexedDB 的自動編號，`replaceAll` 會把它拿掉
   讓本機重配（避免兩台裝置撞號）。所以畫面上那則紀錄手裡的 `logId` 可能已經對不到任何
   一列了。跨裝置穩定的身分是 **`uid`**——但時間軸把紀錄攤成畫面用的物件時**只帶了
   `logId`，沒帶 `uid`**，所以連退路都沒有。
2. **找不到卻不講。** `updateLog` 找不到那一列就 `return null` 靜靜結束，呼叫端的
   try/catch 不會觸發，畫面照樣跳「已更新這則紀錄」。使用者看到的就是「改了，可是沒改到」。

改法：

- 時間軸的紀錄帶上 `uid`
- `Store.findLog(logId, uid)`：先用 `logId`，找不到再用 `uid` 找回來
- `updateLog` / `deleteLog` **找不到就丟錯**（「找不到這則紀錄（可能剛同步過，編號變了），
  請重新整理再試一次」），不要回 `null`
- `updateLog` 寫完**再讀回來對一次**，確定真的寫進去了才算成功

刪除本來也有同一個毛病（找不到就當作成功），一併修掉。

## 按掉今天的提醒，它又跳回來

提醒列上同時有兩種列：**有時間的回撥提醒**，和**下次聯絡日是今天**的。原本的「完成」
只清掉 `remindAt`——可是同一家的下次聯絡日常常就是今天，清掉之後它**立刻以「今天要打」
的身分又出現在同一條列上**。使用者看到的就是「按掉又跳回來」。

（畫面上那一瞬間甚至連標題都會從「⏰ 該回撥了（1）」變成「⏰ 今天要打（1）」，但公司
還是同一家。）

改法：「完成」是把**這一列今天處理掉**，不是只取消那個鬧鐘。

- 一併記下 `dueDoneOn = 今天`，`dueToday()` 當天就不再列這一家
- **下次聯絡日不動**——那是使用者自己排的計畫，卡片上照樣看得到，只是不再從最上面催
- **「今天要打」那種也給「完成」按鈕**：原本只有有鬧鐘的那種才有，所以今天到期的根本
  按不掉
- 提示寫「『◯◯』今天不再提醒」，講明做了什麼、範圍只有今天

## 刪除關係企業時整組一起刪

使用者的要求很直接：「刪除有關聯企業的客戶時，請將全部跟他有連結在一起的公司都刪除」。
合理——會連起來就是因為那是同一個老闆、同一個案子，判斷不打了是整組一起不打；留下半組
在名單上只會每天看到它、又不知道為什麼只剩這幾家。

按「刪除這筆」時現在一次問清楚、一次刪乾淨：

```
確定要從名單刪掉「三大製藥股份有限公司」嗎？

同老闆連結在一起的 1 家也會一起刪掉：
・天輔科技股份有限公司

另外名單裡還有 1 筆同一家公司（來源：B名單.csv），一起刪掉。

連同 3 則通話紀錄會一起刪掉。

總共 3 筆。這個動作救不回來，其他裝置同步後也會一起消失。
```

- **要刪哪幾家一定列出名字**，不是只給數字——一次刪好幾筆，看不到名單就等於閉著眼睛按
- **整組每一家各自的重複**（同一家公司在別份名單裡的那幾筆）也一起收掉，不然刪完還會
  有漏網的跑回來
- 原本的兩段式問句（先問這一筆、再問重複的要不要一起刪）併成一次。重複的留著本來就只會
  變成「刪掉又自己跑回來」，沒有留的理由

## 變更登記改成留歷程，標記帶日期

使用者問了兩件事，答案都不是他想要的：

1. 9/16 查到增資、10/8 查到變更地址，會怎麼顯示？→ **10/8 那次把 9/16 整個蓋掉**，
   篩「增資」撈不到這家，詳細頁也看不出他增過資。
2. 9/16 查到增資、11/20 一樣是那個資本額，增資會消掉嗎？→ **不會**，而且是永遠不會，
   一直掛著到下次查到別的變更為止。

所以名單上的「增資」等於「最後一次變更剛好是增資」，既看不出多久以前，也可能早就
被別的變更吃掉了。想撈最近增資的公司談資金需求，撈到的是一堆半年前的。

### 一件一件記，不是後面蓋前面

`regChange`（單筆）改成 `regChanges`（一串，新到舊）。查到異動就往上加一筆，同一天
同樣種類算同一次，重跑一輪不會多出來。`regChange` 仍然寫最近那一次——還沒更新版本的
裝置只看得懂那一欄。

篩選看的是整串的聯集：9/16 增資、10/8 變更地址，**兩個籤都撈得到這家**。一家同時
算在好幾顆籤裡，所以籤的數字加起來會超過名單筆數，那是對的。

詳細頁的「變更登記」列成時間軸，新的在上面，每一次都寫出改了哪些欄位：

```
變更登記   2026/10/08　變更登記地址
             登記地址：新北市新莊區中正路1號 → 新北市新莊區民安路99號
             最近核准變更日期：2016/03/01 → 2026/09/15
           2026/09/16　增資
             資本總額（仟元）：1,000 → 5,000
           共 2 次，都已依登記更新上面的欄位。
           最近查核 2026/11/20：這天再對過一次，跟登記一樣，沒有新的變動
```

### 卡片標記帶日期

`增資 9/16、變更登記地址 10/8`。變更查到就一直留著、不會自己過期，沒有日期就等於把
半年前的當成新的在打。標記很窄，所以今年的只寫月日，**跨年才補上年份**（`增資 2025/3/5`）
——舊的絕對不能看起來像新的。滑過去的提示是完整日期。

### 同步是聯集，不是二選一

兩台裝置各自查到不同的變更，以前取 `regAt` 比較新的那一份，另一台查到的就整個弄丟。
歷程是只會往上加的紀錄，所以 `mergeState` 改成取兩邊聯集（`mergeRegChanges`），
同一天同樣種類算同一次，誰先誰後合出來都一樣。

已經被蓋掉的歷史救不回來（舊資料只剩最後一次），從這版之後才開始累積。

## 公司名稱的連結改成商工登記公示資料

原本點公司名稱開的是 g0v 社群鏡像（`company.g0v.ronny.tw/id/統編`），使用者要求改成
經濟部的**商工登記公示資料查詢**：

```

```

理由很實際：那是政府的原始資料，跟客戶談的時候拿得出手，而且鏡像的內容未必跟得上

網址一樣用統編那一種（`/fts/company/統編`）——同名公司很多，統編是唯一不會認錯的鍵，

## 回撥備註會被洗掉

使用者回報：「同時使用訪談紀錄儲存及回撥備註，紀錄會被洗掉」。實測四種情境後，
被洗掉的是**回撥備註**，訪談紀錄本身有草稿保護、沒事：

| 情境 | 修正前 |
|---|---|
| 打好訪談內容 → 按時間鈕設提醒 | 訪談內容留著 |
| 提醒已存在 → 改備註 → 按「儲存紀錄」 | **備註退回舊的，改的內容消失** |
| 還沒設提醒 → 只打備註 → 按「儲存紀錄」 | **備註整個消失** |
| 打好訪談內容 → 按「完成／取消提醒」 | 訪談內容留著 |

原因：備註輸入框**只有在按時間鈕的那一刻才被讀取**，它本身什麼都不存。任何讓
詳細頁重畫的動作（儲存紀錄、設提醒、取消提醒、商工登記更新、同步）都會把它換回
資料庫裡的舊值。而且提醒設好之後那個框其實是**動不了的**——想改備註只能重按一次
時間鈕，連時間一起改掉。

### 改法

- **備註有草稿了**，localStorage 與記憶體各一份（理由同通話紀錄的草稿：localStorage
  失效時完全無聲，打到一半的字會在下一次重畫時消失）。重畫、重新整理都填回來。
- **提醒已存在時，打完字 600 毫秒就自己存進去**（失焦也存），只動 `remindNote`、
  **不動提醒時間**。存好後上面那行「約 11:00 回撥 ◯◯」立刻跟著變，旁邊閃一下
  「備註已更新」，名單頁的提醒列也同步換掉。存不進去會講出來，而且字留著。
- **還沒設提醒的備註不寫進追蹤狀態**：同步合併時沒有提醒的備註會被丟掉
  （`if (!out.remindAt) delete out.remindNote`），寫了只是製造「別台看不到」。
  所以只留本機草稿，並在框下面講明「按上面的時間設成提醒之後，備註才會一起存起來」。
- **存通話紀錄前先把備註寫完**。備註是 600 毫秒後才寫的，而存紀錄完會重畫詳細頁；
  兩件事撞在一起，重畫就會把備註換回舊值。所以 `save.onclick` 會先 `await` 備註的
  收尾函式（沒東西要寫時是空轉，重複呼叫沒有副作用）。
- 取消提醒時草稿一起清掉——提醒沒了，備註也沒有意義。

## 刪掉整份名單，公司還是會被下一份帶回來

使用者回報「刪除名單後又會跳回來」。單筆刪除是好的（會記公司墓碑），問題在
**「管理已匯入名單」整份刪掉**：那條路只記了一張「這份名單刪掉了」的墓碑。

那張墓碑只擋得住同步，擋不住下一份名單——同樣那幾百家公司換一個 id 就整批回來。
而且通話紀錄與追蹤狀態沒有清掉，重新匯入同一個檔名時 id 一模一樣，上次記的
下次聯絡日、編輯內容會整包跟著回來。

### 刪整份有兩種意思，不能替使用者猜

「匯錯檔案、重複匯入」跟「這批我都不打了」都是刪整份，但後續完全相反。所以選完
要刪哪一份之後再問一次：

```
「九月名單.csv」的 2 筆客戶、1 則通話紀錄都會刪掉。
要連公司一起排除嗎？排除之後可以在選單「管理已排除的公司」收回來。

  [ 連公司一起排除（2 家，以後別份名單也不要再帶回來） ]
  [ 只刪掉這一份（同一家公司出現在別份名單還是會進來） ]
  [ 取消 ]
```

- **連公司一起排除** → 每一家都記統編與公司名兩把鑰匙的墓碑，跟單筆刪除同一套機制，
  一樣列得進「管理已排除的公司」、一樣收得回來
- **只刪掉這一份** → 只記名單墓碑，行為跟以前一樣

### 順便修掉的

- **通話紀錄與追蹤狀態一起清掉**（只在使用者主動刪整份時；同名重匯是「更新」，
  紀錄必須繼續掛在同一個 id 上，那條路不動）。紀錄要各留一張墓碑，不然同步會把
  它們帶回來——客戶靠名單墓碑擋、追蹤狀態靠客戶已經不在擋，只有紀錄是各認各的 uid。
- **刪完會 `scheduleSync()`**。原本沒有，刪除只留在這台，要等下一次別的動作觸發同步
  才推得出去。
- **刪不掉會講出來**（原本沒有 try，失敗是一個沒人看得到的錯誤）。
- 整份名單動輒幾百筆，墓碑改成批次寫（`addTombstones`）：一筆一趟「讀出整包再寫回去」
  會把畫面卡住。

註：**不會**替整份刪除補 id 墓碑。`deletedBeforeChecker` 會把 id 墓碑當成「使用者刪過
這家公司」而擋掉未來的匯入，那樣「只刪掉這一份」就會變成偷偷排除——正好是這次要修的
問題反過來。

## 編輯客戶資料按了儲存卻沒反應

使用者說「儲存不了」，附的是電話編輯那一塊的截圖。實測後有兩個原因，都是無聲的：

**一、號碼不到 8 碼的電話列會被整列默默丟掉。**
`serializePhones` 只收號碼有 8 碼以上的列。所以：

- 按了「＋ 加一支電話」、只打了分機就存 → 那一列消失，畫面什麼都沒發生
- 號碼少打一碼（例如 `2701902`）→ **原本好好的那支電話直接不見**，畫面還說「已儲存修改」

第二個比第一個糟：那是把資料弄丟了還回報成功。

現在存之前先擋下來，並且講清楚是哪一支、少了什麼：

```
電話還不能存：第 3 支只填了分機、號碼還沒填。請補上號碼，或按那一列的「刪除」。
```

那一列的號碼框會標紅，視窗不關，打的字全部留著。

**二、寫入失敗完全無聲。**
`save.onclick` 裡的 `await saveState(...)` 連 try 都沒有——寫入失敗就是一個沒人看得到的
unhandled rejection：視窗照樣關掉、改的東西沒了，使用者只會以為自己沒按到。現在失敗會
把原因留在表單上（不是只靠兩秒就消失的 toast），視窗不關、內容留著，再按一次就好。
而且寫完會讀回來確認，讀不回來也算失敗。「還原成名單原始內容」同樣補上。

**三、沒改到東西不要說成「已清除先前的修改」。**
本來只要算出來的 `edits` 是空的就講這句。可是「我沒改東西」跟「我把先前的修改清掉了」
是兩件事，前者看到那句話只會以為剛打的東西被丟了。現在分開講：沒有先前的修改就說
「內容沒有變動」。

## 拜訪準備與拜訪紀錄

系統原本只做電話那一段：名單進來、排隊打、記結果。但業務的工作是電話**加**拜訪，
拜訪那一段以前完全沒接住——出門前要自己在詳細頁捲三屏拼湊，回來記的東西又跟
通話混在同一個框裡，之後要找「上次拜訪誰說要買設備」還是得整篇讀。

### 拜訪準備：出門前一頁紙

詳細頁的「拜訪準備」按鈕開一頁摘要，順序照談話會用到的順序排：

| 區塊 | 內容 | 來源 |
|---|---|---|
| 基本資料 | 統編、負責人、KEYMAN（含判讀依據）、產業、成立年（算成幾年）、資本額與規模、電話、實際／登記地址、行銷區域 | 名單、編輯、商工登記 |
| 登記動態 | 最近核准變更與歷次異動（增資 20000 → 30000 這種 from → to） | 商工登記查核 |
| 往來情形 | 有沒有跟中租往來與原文片段、往來銀行／同業／中租其他單位、有沒有拜訪過 | 訪談內容判讀 |
| 同老闆的公司 | 各家的下次聯絡日、洽談狀態、有沒有中租往來 | 關係企業連結 |
| 最近談了什麼 | 最近三則（自己記的、名單檔的、同組的一起排） | 通話紀錄＋訪談內容 |
| 這次要問 | 見下方 | 從上面幾區推出來的 |

「這次要問」不是固定問卷。剛增資的問錢要用在哪、有往來銀行的問額度用了多少、跟中租
有往來的問到期與加碼、訪談看不出 KEYMAN 的先問財務誰拍板——每家不一樣，而且把查到的
數字直接帶在題目裡，對方一聽就知道你做過功課。上次紀錄裡寫了「約 9/30 再聯絡」之類的
承諾會排在第一題（先接上次的話）。通用的四題（營收訂單、半年內資金需求、額度使用率、
可提供的資料）固定放最後。問題前面有勾勾，現場一邊問一邊勾，勾掉的會淡掉。

三個動作：**列印／存成 PDF**（只印那一頁，底下的名單與浮層都藏起來）、**複製文字**
（整頁的純文字版，貼到 LINE 或行事曆備註；畫面跟純文字是同一份資料一起組的，不會一邊
有一邊沒有）、**導航到實際地址**（Google 地圖路線）。最後一顆「記錄拜訪結果」直接跳回
詳細頁、把拜訪表單攤開。

### 記錄這次拜訪：跟記通話分開

電話記的是講了什麼、下次何時打；拜訪要記的是**見到誰、資金需求落在哪、下一步是送件
還是再約**。所以另開一段短表單，欄位是選的不是打的：

- 拜訪日期（預設今天，可補記前幾天的）、見到誰（KEYMAN 與負責人先列進候選）
- 談了什麼（自由文字；裡面寫「約10/15再談」會跟通話紀錄一樣自動補下次聯絡日）
- 資金需求：週轉金／購置設備／擴廠／備料／代償／暫無需求，可複選；「暫無需求」跟其他互斥
- 下一步：送資料評估／再約拜訪／電話追蹤／先不追
- 有沒有機會：直接寫進「有機會／無機會」標記（那個欄位本來就只收手動判斷，這裡也是手動）
- 下次聯絡日與快捷鍵，撞到假日一樣順延

存成一則 `kind='visit'` 的紀錄，內容組成「實地拜訪，見到 X。…／資金需求：…／下一步：…」。
時間軸上標「我的拜訪」、點換成另一個顏色；同老闆的公司一樣互通；匯出 Excel 會帶到。

**「有拜訪」的判讀先認這個標記**，沒有才回頭從訪談字面猜。字面判讀會漏（寫「到廠看了
設備」就抓不到），明講的不該再被猜錯。內容開頭固定寫「實地拜訪」，是為了匯出再匯回來
（標記會掉）時，字面判讀也還認得出這是一次拜訪。

補記前幾天的拜訪不會把「最近聯絡日」往回拉：只有拜訪日期不早於原本的最近聯絡日才更新。
表單預設是收起來的（不是每次開詳細頁都是剛拜訪回來），寫到一半會存草稿，回來自動攤開。
存不進去的原因會留在表單上，跟通話紀錄同一套。

## 撈本月新公司：每月的設立／變更登記清冊

使用者的瓶頸是「找不到新客戶」——名單打完就沒了。以前每個月自己去經濟部網站下載
清冊、再手動篩，現在由 GitHub Actions 每月抓好，網站上一按就能匯入。

### 資料從哪裡來

商工登記的**「公司所營事業項目清冊」**（`serv.gcis.nat.gov.tw/pub/cmpy/reportCity.jsp`
列出的每縣市每月 PDF）。選這份而不是基本清冊，是因為它多兩欄：

| 欄位 | 為什麼重要 |
|---|---|
| 案由或變更事項 | 增資、發行新股、公司所在地、改選董事…——**「剛增資」就是最強的資金訊號**，以前根本看不到 |
| 營業項目代碼 | 名字看不出行業的（「XX 有限公司」）用代碼補；有 C（製造）、E（營造）、G（運輸）就當作有設備標的 |

實測 115 年 8 月：新北變更 2,529 家（增資＋發行新股 244 家）、設立 507 家；臺北變更 4,203 家、設立 454 家。

探測過的其他路都不通：商工開放資料 API 帶任何範圍條件都回空的（只能一家一家用統編查）；
findbiz 有 Cloudflare 擋；資料開放平臺搜尋 API 只收 POST。清冊網址不用 session，直接抓得到。

### 為什麼在 GitHub Actions，不在瀏覽器

政府網站沒有 CORS，瀏覽器抓不到；開發環境也連不上政府網站，只有 Actions 的 runner 出得去。
所以 `.github/workflows/monthly-leads.yml` **每月 8 日台灣時間 09:00**（清冊在次月初產製，例如
8 月的清冊 9/5 出）跑 `tools/fetch-leads.mjs`，把新竹以北加宜蘭七個縣市的設立、變更清冊
轉成 CSV，連同 `leads/index.json` 一起 commit 回 repo，網站從自己的網址讀。也可以在 Actions
頁手動觸發，指定期別。只留最近 6 期。

### PDF 怎麼解析

用 `pdftotext -tsv`（每個字帶座標），不用 `-layout` 的純文字。清冊的儲存格會換行
（長公司名、長地址、代表人是外國人），換行那一截在 `-layout` 裡的字元位置跟主列對不上
——中文字寬不均，同一個 x 在不同行會落到不同的字元欄，照欄位字元數切會把地址的下半段接到
代表人去。座標不會騙人：JasperReports 的欄位左緣整份文件固定。

做法是兩趟：第一趟從「每個欄位都認得出來」的主列（統編 8 碼、登記機關、縣市開頭的地址、
數字資本額、`115/08/18` 日期、`C801010` 這種代碼）量出每一欄的左緣；第二趟每個字照 x 落在
哪一欄歸位，主列開新的一筆、其餘行接到上一筆。表頭、頁尾（「第 1 頁/共 570 頁」）濾掉。
沒有資本額的只有外國公司分公司與辦事處，那不是解析錯，是登記上就沒有。

### 獨立網站：`leads/index.html`

使用者要求這個功能**從電話推廣名單系統拉出來、獨立成一個網站**（網址是
`…/asaaaa/leads/`，⋯ 選單裡有連結）。分開是對的：那邊是「自己的客戶」，資料只在瀏覽器裡、
有密碼；這邊是政府的公開清冊，誰都能看，不用密碼、不存任何東西。兩邊的交集只有一個 CSV。

單一個 HTML 檔，沒有相依套件。讀同目錄的 `index.json`，勾了哪些縣市、清冊才下載那幾份 CSV
（新北變更一份 1MB，不勾不載）。篩選：清冊（預設只勾變更：設立的多半是剛開的小公司還不能貸）、
縣市、案由（預設只留增資／發行新股）、行業（依營業項目代碼第一碼：C 製造、E 營造、G 運輸…）、
資本額（預設 500 萬～6,000 萬）、略過投資控股、關鍵字。卡片上公司名連到商工登記公示資料、
地址連到地圖。

**「匯出 CSV」**的欄位跟 Actions 產的一模一樣，拖進電話推廣名單系統的「新增客戶」會被認成
登記清冊，走它的匯入流程（再問一次條件，多一顆「只要增資的」）。

匯入時的兩個調整：
- **成立年只看「核准設立日期」**。變更清冊的日期是「核准變更日期」，以前用「核准」去對，
  換負責人那天就變成成立年，整批公司都變成今年才成立的。
- 案由與營業項目寫進訪談內容當背景（「115年8月變更登記：增資。營業項目：…」），卡片上看得到、
  搜尋找得到。**故意不帶 `115/08/18` 這種日期**：parseNotes 看到日期就當成一通電話，
  這家會從「未撥打」變成「已聯絡」。

## 今日推薦：每天把值得推廣的挑出來

使用者問能不能「建立一個跟我一樣的企金業務，每天自動幫我篩選網站內的名單，挑出值得推廣的」。
做成「今日推薦」分頁：每天打開網站就重算一次，把名單裡值得打的挑出來、排好順序，
**每一家都寫清楚為什麼**。

用規則加分，不用任何模型：

| 加分 | 分數 | 扣分 | 分數 |
|---|---|---|---|
| 120 天內增資（商工登記查到的） | +40 | 剛減資 | −15 |
| 清冊匯進來的增資／發行新股 | +35 | 投資／控股類、沒有設備標的 | −25 |
| 你標了有機會 | +30 | 大企部範疇（資本額 > 1 億） | −20 |
| 逾期／今天到期 | +15 | 資本額不到 100 萬 | −15 |
| 負責人剛換 | +12 | 沒有電話 | −25 |
| 以前往來過（回頭客） | +12 | 範圍外，要走協銷 | −30 |
| 有設備標的（製造／營造／運輸） | +12 | | |
| 資本額 500 萬～6,000 萬 | +10 | | |
| 中租往來中（談加碼／續約） | +8 | | |
| 還沒打過、三個月以上沒聯絡、有機會但還沒拜訪、剛搬 | +8 | | |
| 談過但沒排下次 | +6 | | |
| 知道 KEYMAN、同老闆多家 | +5／+4 | | |

30 分以下不列；禁止推廣、標了無機會、已設回撥提醒、按過「略過 30 天」的不列。
只列前 30 家：打完這些明天再看。

為什麼不用模型：每一分都講得出理由，卡片上就寫「增資 9/10 ＋ 製造業 ＋ 有機會」，業務看一眼
就能判斷同不同意，錯了也知道錯在哪一條。而且全部在瀏覽器裡算，名單不用離開這台裝置。
名單只有幾百到幾千筆，每次開網站重算不到一秒，「每天自動」就是每天打開就重算。

兩顆按鈕：**排今天**把下次聯絡日設成今天（今日待打就會有它），**略過 30 天**記在追蹤狀態裡
（`pickSkipUntil`，會跟著同步）。最上面還有「前 10 家排到今天」，早上按一下就有東西打。

## 找電話：Google 地圖（Places API）

使用者的做法：沒電話的客戶，Google 搜公司名，電話取自官網或 Google 地圖的店家資料，
找不到就刪掉。名單裡沒電話的有兩千七百多家（多半是清冊匯進來的），一家一家搜是一週的工作。

接的是 Google 地圖同一份資料的正規管道：**Places API (New) 的文字搜尋**，用「公司名＋地址」查，
回來的店家有電話、地址、官網、地圖連結。**從使用者自己的瀏覽器直接查**（API 允許跨網域，
金鑰用「網站限制」綁在這個網址），送出去的只有公司名與地址，都是登記上的公開資料；
金鑰存在這台裝置的 localStorage，不進同步檔。這裡的開發環境連不上 Google，所以只能
用模擬的回應測介面與判斷邏輯，真的查要使用者自己貼金鑰試。

### 對不對得上要自己判

Google 回的可能是隔壁店。分三級：

| 級別 | 條件 | 怎麼處理 |
|---|---|---|
| 確定 | 公司名去掉「股份有限公司」後互相包含，**而且**地址在同一個區（或同一個門牌） | 整批找時直接填入 |
| 疑似 | 只有名字像；或名字不像但**門牌一樣** | 列出來，一家一家看了再採用 |
| 不像 | 其他 | 當找不到 |

門牌要「路名＋段＋號」整個對上：同一條路不算——第一版只比路名，隔壁的便利商店就被當成疑似。
比之前先正規化：台→臺、「一段」→「1段」、全形數字→半形。寧可沒電話也不要存錯的號碼。

### 存在哪

採用的電話存成**編輯覆蓋**（`edits.phoneRaw`，跟手動改電話一樣，重新匯入不會被蓋掉、會跟著
同步），另外記 `phoneSource`（店家名、地址、地圖連結），詳細頁標一行「電話來自 Google 地圖：
…」，打過去講錯公司名才有得對。**不寫通話紀錄**：紀錄會把最近聯絡日改成今天，看起來像打過了。

### 整批找

選單「幫沒電話的找電話」拿的是「全部名單」**目前篩出來**的沒電話客戶：先用篩選（變更登記＝
增資、產業別、客戶規模）縮到值得打的一兩百家再找，兩千多家全找一遍要一小時又花錢。
確定的直接填，疑似的列出來逐一確認，找不到的列成一批、一顆鈕刪掉（要確認，會同步）。
金鑰壞掉時前幾家都失敗就停，不會撞完整批。

費用：含電話欄位的文字搜尋是 Pro 級，每千次約 US$32，Google 每月送 US$200 額度（約六千次）。
金鑰要在 Google Cloud 啟用 Places API (New)、用「網站」限制到這個網址、API 限制只勾 Places；
設定視窗裡有步驟。

## 每天打得完幾家

使用者把匯進來的名單篩過、一筆一筆排上下次聯絡日之後說：「短期內要聯絡的名單太多。」

原本只有「把今天要聯絡的分散到未來 15 個工作天」。那顆只處理**今天（含逾期）**那一批，
而且是平均切——未來每天本來就已經塞滿的時候，它反而把今天的再疊上去。而且畫面上從來
沒有地方告訴你「9/28 有 42 家、9/29 有 38 家、10/1 只有 3 家」，「太多」只能用感覺的。

所以補兩件事，在 ⋯ 選單的「每天打得完幾家」裡：

### 一、看得到每個上班日各有幾家

```
我一天最多打 [ 20 ] 家   [ 照上限重排 ]

接下來 20 個上班日有 2 天超過上限，多出 23 家
這 20 天共 72 家；其中 8 家已逾期，算在第一個上班日；
另外有 1 家排在 2026/11/03 之後，沒算進來。點任一天可以只看那天的名單。

2026/10/5（一）  ████████████████████  38 家   ← 紅色
2026/10/6（二）  █████████████         25 家   ← 紅色
2026/10/7（三）  ██                     3 家
```

- **逾期的算在第一個上班日**——它們本來就該處理了，另外列一行只會讓人以為還有得拖
- **下次聯絡日落在週末或國定假日的算到下一個上班日**：那天本來就打不了電話，列在那裡
  會讓當天看起來是空的
- 點任一天就把名單篩成那一天

### 二、照上限把超過的往後挪

一天一天往後走：那天的池子（前一天擠下來的 ＋ 原本排那天的）照優先順序留下上限那麼多家，
其餘整批推到下一個上班日。**只會往後、不會往前**——把客戶提前打不是使用者要的。

誰留在前面：

1. **已經被擠過一次的**（原訂日期最早）——不然同一批會一直被往後推，永遠排不到
2. 你自己標過「有機會」的
3. 最近查到變更登記的（增資、換負責人這種有資金需求的訊號）
4. 資本額大的
5. 公司名稱（只是讓結果穩定，不要每次按都換一個順序）

**已經約好回撥時間的（有設提醒的）完全不動**，但會佔掉當天的額度——那是跟客戶約好的，
不能因為額度滿了就搬走。

復原沿用原本的「復原剛才的分散」，不另外做一個。上限存在 `daily-cap`，跟著雲端同步，
在電腦上設好手機打開要是同一個數字。

註：原本那顆「把今天要聯絡的分散到未來 15 個工作天」留著沒動。兩顆的差別是——那顆把
今天那批平均攤到 15 天（不管那些天原本有多少家），這顆是照上限把**全部**排定的重新攤平。
短期內爆量用這顆。

## 連結關係企業：名單外查詢調到上面

使用者說「名單外查詢公司的那欄上調到上面，我比較常用這個功能」。

合理——要連的關企多半就是他當下知道名字、但名單裡沒有的那一家。名單內的清單有好幾百列，
擺在前面等於每次都要先捲過去才看得到查詢框。

現在的順序是：目前選的 →「名單外的關係企業」查詢 → 名單內的公司（勾選）。打開視窗時
**游標直接落在查詢框**，不用先點一下。名單內那段補了自己的標題與分隔線，兩段才分得開。

兩個清單原本都叫 `.group-list`，換順序之後「第一個 .group-list」就認錯人了，所以各給一個
名字：`group-list-mine`（名單內）與 `group-list-found`（查到的）。
